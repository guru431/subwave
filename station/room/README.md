# Комната — чат станции

Слушатели пишут в комнату из плеера, ведущий читает новое навыком `chat` и
отвечает **голосом в эфире**. В самой комнате реплик ведущего нет: там видно
только то, что написали люди.

Отдельный контейнер, а не часть контроллера, по двум причинам. У апстрима
понятия чата нет вовсе — добавлять его значило бы держать форк ещё и под это.
И слушателю нужен путь, открытый **без админского пароля**: у контроллера весь
поиск по библиотеке и всё, что похоже на ленту, закрыто `requireAdmin`.

Стиль — как у [`tts-bridge/bridge.py`](../tts-bridge/bridge.py): стандартная библиотека
плюс `sqlite3`, никаких фреймворков. Единственное исключение — пакет
`cryptography` для Web Push (раздел ниже, там же почему).

## Поверхность

| Метод | Назначение |
|---|---|
| `GET /health` | `{"ok": true}` |
| `POST /messages` | `{text}` + заголовки личности → `{"id": N, "at": …}`, код 201 |
| `GET /messages?since=&limit=` | лента для плеера (по умолчанию 50 последних) |
| `GET /unread?since=&limit=` | то же для навыка ведущего (по умолчанию 20) |
| `GET /resolve?q=` | сверка с коллекцией: `{"exact": …\|null, "alternatives": [...]}` |
| `GET /download?id=` | файл прозвучавшего трека; отказ — `.txt` с честным кодом |
| `GET /push/key` | открытый ключ VAPID для `PushManager.subscribe()` |
| `POST /push/subscribe` | `{subscription}` + заголовки личности → 201; повторная подписка обновляет имя |
| `POST /push/unsubscribe` | `{endpoint}` → `{"ok": true, "removed": …}` |
| `GET /dislikes` | отметки «не нравится» этого слушателя по песням окна станции |
| `POST /dislikes` | `{songId, kind, on}` + заголовки личности — поставить или снять отметку |
| `GET /admin/dislikes` | предложения блокировки для владельца: `{artists, tracks}` |
| `POST /admin/dislikes/decide` | `{kind, key, action}` — решение владельца: `keep` или `blocked` |

`/messages` и `/unread` отвечают одинаково и оставлены двумя путями намеренно:
по логу Caddy сразу видно, кто приходил — плеер за лентой или ведущий за новым.

Наружу комната смотрит через Caddy по префиксу `/room/*`, поэтому её
собственные пути — без него: `https://<station-domain>/room/health` доходит до
`GET /health`.

## Личность слушателя

Заголовки `X-Listener-Id` и `X-Listener-Name`. Ни паролей, ни базы
пользователей: станция закрыта общим паролем, аудитория — семья, а подмена
имени даёт ровно то, что и так доступно — написать под чужим именем. Плеер
хранит `{id, name}` в `localStorage` (`web/lib/listener.ts`, фича «ящик чата»).

`id` нужен не для доверия, а для частотного лимита: снаружи все слушатели
приходят в стек **одним адресом** (Caddy переписывает `X-Forwarded-*` для пиров
вне `trusted_proxies`, и Apache туда не входит), поэтому лимит по IP считал бы
семью за одного человека.

**Имя едет percent-encoded.** HTTP-заголовки по RFC 7230 — latin-1, и кириллица
в них не проходит: `http.client` отказывается кодировать её ещё на стороне
клиента. Плеер шлёт `encodeURIComponent(name)`, комната разворачивает.

## Что комната делает с текстом

Чистит тем же приёмом, каким апстрим чистит текст заказа
(`sanitizeRequestText` в `controller/src/routes/request.ts`): роль-маркеры
шаблонов чата, любые теги, поддельные начала реплик, семейство «игнорируй
предыдущие инструкции», двойные кавычки. Сообщение уходит в промпт ведущего —
то есть комната это вторая дверь в тот же промпт, и закрывать её надо тем же
самым.

Длина — 280 символов, имя — 40: те же цифры, что у заказа
(`REQUEST_TEXT_MAX` / `REQUEST_NAME_MAX`). Слишком длинное сообщение
**отвергается, а не обрезается**: обрезка режет фразу на полуслове, и ведущий
отвечает на половину вопроса.

Частота — не больше `RATE_MAX` сообщений за `RATE_SECONDS` с одного
`X-Listener-Id` (по умолчанию 10 в минуту) и не больше `RATE_GLOBAL` за то же
окно на всю комнату (по умолчанию 30 в минуту; сверх — 429 «чат переполнен»).
Общий потолок нужен потому, что id выбирает сам клиент: новый id на каждое
сообщение снимал личный лимит целиком, а путь анонимный и открыт из интернета.
30 в минуту — с запасом для семьи из нескольких человек (оживлённый чат — с
десяток реплик в минуту) и предел роста базы: не больше 43 тыс. сообщений
(по 280 символов) в сутки за весь срок хранения `RETENTION_DAYS`.
Цена — тот, кто перебирает id, может на время забить чат и остальным; ресурсы
станции он при этом не съест. Оба счёта — под одной блокировкой с записью.

Сверка `/resolve` — не больше `RESOLVE_MAX` за `RATE_SECONDS` на всю комнату
(по умолчанию 30 в минуту). Личности у сверки нет — плеер шлёт её без
заголовков, — а каждая стоит до шести походов в Navidrome (`MAX_ATTEMPTS`), так
что без потолка ручка была открытым усилителем нагрузки. Один слушатель, набирая
заказ, тратит 5–15 сверок (пауза в наборе — 400 мс); сверх потолка — 429, и плеер
просто не показывает подсказку: заказ всё равно уходит текстом.

## Сверка с коллекцией

`GET /resolve` ходит в Navidrome по Subsonic API (`search3`) и отвечает всегда
одной формой. `exact` заполняется, когда нормализованный запрос совпал с
«артист — название» **целиком**; совпадение по одному названию точным не
считается — «Звезда» это и отдельный трек, и часть другого названия.

### Командное слово: «Включи» обнуляло сверку целиком

Слушатель пишет не «Артист — Название», а «Включи Агата Кристи - На войне».
Navidrome ищет по всем словам запроса сразу, поэтому одно служебное слово
давало **ноль** — и сверка честно отвечала «в коллекции такого нет» про песню,
которая в коллекции есть. Из 42 заказов станции за 21–22.09 по этой причине не
резолвился **ни один**: `songId` не уезжал, и заказ уходил разбираться LLM.

`strip_command()` срезает командное начало («включи», «поставь», «врубай»,
«сыграй», `play` …) вместе со служебным словом за ним («песню», «группу»).
Режется по исходным токенам, а не по нормализованным: в остатке должен уцелеть
разделитель, который набрал слушатель. Запрос, состоящий из одних служебных
слов, возвращается нетронутым — пустой запрос в Navidrome бессмыслен.

Команда бывает и в середине: «Передай привет Диме Ефимову, поставь песню Прыгну
со скалы» — тоже реальный заказ. Срезанием начала её не достать, поэтому при
**пустой** выдаче делается вторая попытка хвостом после последней команды
(`tail_after_command()`). Второй запрос уходит только при промахе первого:
когда трек нашёлся, догадываться не о чем.

### Приписка и падеж: заходы `search_attempts()`

Заказ редко приходит голым названием. `search_attempts()` выдаёт пары «запрос,
вправе ли он дать точный ответ» — от точного к отчаянному, и следующий заход
уходит **только при пустой выдаче** предыдущего:

| Заход | Пример | Точный ответ? |
|---|---|---|
| без командного начала | «Включи Кино - Пой» → «Кино - Пой» | да |
| хвост после команды в середине | «передай привет …, поставь X» → «X» | да |
| усечённые основы | «поставь чичерину» → «поставь чичерин» | нет |
| префиксы в 3, 2 и 1 слово | «rammstein и передай привет Диме» → «rammstein» | нет |

**Про усечение.** «Поставь чичерину», «включи агату кристи» — винительный
падеж, и такого слова в коллекции нет вовсе. Navidrome ищет **по началу
слова**, поэтому «чичерин» находит «Чичерину», а «агат крист» — «Агату
Кристи»; словаря и морфологии для этого не нужно. Латиница не трогается —
падежей у неё нет, а усечение даёт мусор. Короткие слова тоже: «Кино» стало бы
«Ки».

**Заходов не больше `MAX_ATTEMPTS` (6), и это не запас, а ограничение.** Ящик
заказа спрашивает сверку на каждой паузе в наборе, а комната однопоточна:
перебор всех префиксов длинной фразы складывался в секунды и ронял сверку в
502 при череде заказов подряд. Поэтому префиксы пробуются не всех длин подряд,
а только 3, 2 и 1 слово — название редко длиннее трёх слов.

**Точным может быть только неурезанный запрос.** Снятие команды и взятие хвоста
ничего из заказанного не теряют, а усечение и обрезка — теряют: «Сектор Газа
Гуляй мужик» сокращается до «Сектор Газа», единственный трек группы —
«Демобилизация», и назвать её точным совпадением значит отправить в эфир чужую
песню с видом уверенности. Такой кандидат уходит в `alternatives` — подсказка,
а не ответ. Это отдельный тест.

### Неточное название: единственный кандидат

Название слушатель помнит приблизительно — «На войне» про трек «Как на войне».
Поэтому единственный кандидат, в котором нашлись **все** слова запроса, тоже
считается точным: выбирать не из чего, а ответ «точного совпадения нет» там,
где совпадение ровно одно, — это тот же отказ найти имеющееся. Несколько
кандидатов остаются выбором слушателя, как и раньше.

Единственность **не** отменяет правила про версии: если кандидат отличается от
запроса только скобочным суффиксом, это `Song (Live)` против `Song` — разные
записи, и подставлять одну вместо другой нельзя. Это отдельный тест.

Нормализация — `norm()` из [`normalize.py`](normalize.py): своя копия комнаты,
снятая с каталога коллекции, которым станция пользовалась до выделения в форк.
Комната сверяет запрос с Navidrome, а не с тем каталогом, поэтому расхождение
копий безопасно. Заодно наследуется
поведение, которое здесь ровно кстати: скобочный суффикс `norm()` не снимает,
поэтому `Song (Live)` и `Song` остаются разными записями.

Сбой похода в Navidrome отвечает **502**, а не пустым списком: «в коллекции
нет» и «сверка не состоялась» — разные ответы, и плеер показывает слушателю
только первый.

Учётка — **отдельная, читающая**: `subwave-room`, `isAdmin=false`. Комната
смотрит наружу, и админский пароль Navidrome ей не нужен.

## Web Push: важное — и при закрытой вкладке

Уведомление страницы (`web/lib/roomNotify.ts`) живёт, пока жива вкладка:
свёрнутую браузер замораживает, закрытую не будит ничто. Будит только
push-сервис браузера (FCM у Chrome и Edge, autopush у Firefox, Apple у Safari),
и сообщение ему шлёт комната — по подписке, которую плеер оформляет тем же
переключателем «Уведомлять о важном».

**Что считается важным** — то же правило, что у плеера (`web/lib/roomRules.ts`),
повторённое в [`notify.py`](notify.py) на тех же тестовых примерах:

| Событие | Кому | Откуда комната знает |
|---|---|---|
| каждое сообщение другого слушателя | всем подписчикам, кроме автора | из своего `POST /messages`; автор узнаётся по id слушателя и по имени — так молчит и его другое устройство |
| ответ ведущего в чат (`kind == "chat"`) | всем подписчикам | опросом ленты станции `/session` раз в 20 с; первый опрос только засевает виденное — история не звонит; без подписчиков станцию не спрашивает |

Так решил владелец 2026-09-23. До того громким было только упоминание имени, и на
«Всем привет!» от другого слушателя не всплывало ничего — это и было жалобой «нет
всплывающих уведомлений из чата».

**Протокол** — RFC 8030/8291/8292, в [`push.py`](push.py): шифрование
`aes128gcm` сверено в тесте с примером из приложения A RFC 8291 байт в байт,
подпись VAPID — ES256. Писать это на стандартной библиотеке (ECDH P-256, HKDF,
AES-GCM, ECDSA) значило бы несколько сотен строк криптографии, ошибку в которых
увидит только push-сервис, молча отбросив сообщение. Поэтому `cryptography`,
версия приколочена в Dockerfile. Проверено и на живом FCM (2026-09-23): подписка
безголового Chrome, отправка боевым кодом из контейнера — `201 Created`; мёртвая
подписка дала `410`, и комната забывает её сама.

**Ключ VAPID** — `vapid.pem` на томе рядом с базой, создаётся при первом старте
(0600). Подписка браузера привязана к открытому ключу: пересозданный ключ
обесценивает все подписки разом, поэтому его место — том, а не образ. Плеер,
встретив подписку на прежний ключ, снимает её и оформляет заново. Переменные
`VAPID_KEY` — путь к ключу, по умолчанию `/data/vapid.pem`. `PUSH_SUBJECT` —
контакт в подписи (`https://<домен станции>` или `mailto:…`) — **обязателен**:
умолчания с чужим доменом нет, и без переменной комната не стартует. Значение —
в `.env` стека, в compose — `PUSH_SUBJECT: ${PUSH_SUBJECT}`.

**Адрес подписки проверяется**: только `https` и только хосты push-сервисов
(`PUSH_HOSTS` в `push.py`). Адрес приходит от кого угодно снаружи, а комната
потом сама ходит по нему POST-ом — без белого списка она стала бы прокси в LAN.
Подписок не больше 500, на один `X-Listener-Id` — не больше `PUSH_PER_LISTENER`
(3): новая сверх него вытесняет самую старую того же слушателя (один id — один
браузер, лишние адреса у него — брошенные прежние подписки). Переподписка
обновляет имя, но счётчик отказов не обнуляет: переподписаться может кто угодно
снаружи. 404/410 от push-сервиса удаляют подписку сразу, пять временных отказов
подряд — тоже.

**Рассылка — один фоновый поток на всю комнату** с очередью по адресу подписки:
новое сообщение заменяет неотправленное тому же адресату (в шторке у чата всё
равно одна карточка), поэтому очередь не длиннее числа подписок. Прежде каждое
сообщение запускало свой поток — до 500 подписок последовательно, до 10 с на
каждую.

Тег уведомления — `subwave-chat`, тот же, что у уведомления страницы: живая
скрытая вкладка и push не выстроят в шторке двух карточек об одном. Видимая
вкладка push не показывает вовсе — там тост. Нажатие открывает плеер с чатом.

**Чего нет**: на iPhone push приходит только в установленное приложение (так
устроен Safari), и переключатель там об этом и говорит. Комната не знает, кто из
подписчиков слушает эфир, поэтому ответ ведущего получают все подписчики. И
видимая вкладка push не показывает: на компьютере окно плеера, открытое, но
закрытое другими окнами, браузер может считать видимым — тогда о сообщении
скажет только тост в самом плеере.

## Дизлайки: сигнал владельцу, а не выключатель

Слушатель отмечает в плеере «не нравится песня» или «не нравится исполнитель»
(кнопка 👎 — фича «дизлайки», `../docs/web-changes.md`). Эфир от отметки не
меняется: из отметок владелец получает предложения на вкладке **Admin → Library →
Blocked** и решает сам. Спека —
[дизлайки слушателей](../docs/specs/2026-09-24-listener-dislikes-design.md).

**Отметить можно только песню из окна станции** — ту же, что можно скачать:
текущую и прозвучавшие. Исполнитель, название и альбом берутся из окна, а не из
запроса. Цель отметки исполнителя — `norm(artist)`, поэтому «Ёлка» и «Елка»,
`AC/DC` и `AC DC` — один исполнитель. Снятие отметки тоже сверяется с окном:
без него не узнать исполнителя песни.

**Порог низкий нарочно:** песня — с первого дизлайка, исполнитель — с явного
дизлайка или с двух разных дизлайкнутых песен (`dislikes.py`). Решение владельца
(`keep` или `blocked`) прячет строку, пока не придёт дизлайк строго новее
решения. Время дизлайков и решений — с миллисекундами: иначе решение и дизлайк
в одну секунду были бы неразличимы.

**Пароль владельца проверяет контроллер.** Своего пароля у комнаты нет:
заголовок `Authorization` уходит в `GET /settings` контроллера, тем же запросом
админка проверяет вход (`admin.py`). Перебирать пароль через комнату бесполезно —
после 10 неудач контроллер закрывает вход её адресу на 15 минут, и комната
отдаёт его 429 с `Retry-After`. `WWW-Authenticate` комната не шлёт: на него
браузер поднял бы поверх админки своё окно входа. Снаружи `/room/admin` к тому
же закрыт правилом Apache «только из приватных сетей».

Записей не больше 5000 (`Config.dislikes_max`): адрес открыт наружу. Отметки
хранятся бессрочно — чистка по возрасту (`RETENTION_DAYS`) касается только ленты.

**Восстановление после спуфинга.** Спека §8 сознательно принимает подмену `id`:
лимит защищает от переполнения таблицы, а не от подлога. Забитая таблица держит
`429` для новых отметок навсегда, а очистки у владельца нет (спека §7). Кто её
наполнил — с хоста, изнутри контейнера комнаты:

```bash
sudo docker exec sub-wave-room python -c "
import sqlite3
for row in sqlite3.connect('/data/room.db').execute(
        'SELECT listener_id, COUNT(*) FROM dislikes GROUP BY 1 ORDER BY 2 DESC LIMIT 10'):
    print(row)
"
```

Удалить его записи (подставить найденные `listener_id`):

```bash
sudo docker exec sub-wave-room python -c "
import sqlite3
db = sqlite3.connect('/data/room.db')
db.execute('DELETE FROM dislikes WHERE listener_id IN (?)', ('<listener_id>',))
db.commit()
"
```

Путь `/data/room.db` — это `ROOM_DB` контейнера `room`
([`../deploy/docker-compose.override.yml`](../deploy/docker-compose.override.yml)),
том смонтирован с хоста (`./room:/data`); тот же путь — дефолт в самом
[`server.py`](server.py) (`ROOM_DB`, если переменная не задана).

Проверено на живой станции 2026-09-24: отметка и строка у владельца с именем,

## База

SQLite на томе хоста — `<deploy-dir>/subwave/room/room.db`. **Не на шаре**:
SQLite на CIFS повреждается, это правило проекта. Вторая таблица —
`push_subscriptions` (адрес, ключи, id и имя слушателя, счётчик отказов).

Ещё две — `dislikes` (отметки слушателей) и `dislike_decisions` (решения
владельца); обе заводит `CREATE TABLE IF NOT EXISTS` при старте, так что прежний
`room.db` получает их сам.

Одна таблица `messages`: она же лента, она же источник ответа «сколько этот
слушатель написал за минуту». Сообщения старше `RETENTION_DAYS` (14) удаляются
при записи. `AUTOINCREMENT` в схеме стоит осознанно: без него SQLite
переиспользует освободившиеся id, и курсор навыка («прочитано до N») начал бы
пропускать новые сообщения с уже виденными номерами.

## Сборка

Контекст сборки — этот каталог (`normalize.py` лежит рядом с прочими модулями).

```bash
# на хосте станции, в клоне ~/radio (его обновляет station/tools/push-to-station.sh)
cd ~/radio && bash station/tools/guarded.sh sudo docker build -t subwave-room:2 station/room
cd <deploy-dir>/subwave && sudo docker compose up -d room
```

Переменные (`NAVIDROME_URL`, `NAVIDROME_USER`, `NAVIDROME_PASS`, `PUSH_SUBJECT`)
лежат в `.env` станции; потолки (`RATE_SECONDS`, `RATE_MAX`, `RATE_GLOBAL`,
`RESOLVE_MAX`, `PUSH_PER_LISTENER`, `RETENTION_DAYS`) умолчаниями в
[`server.py`](server.py), переопределяются в `environment:` контейнера; подключение контейнера и маршрут `/room/*` — в
[`../deploy/docker-compose.override.yml`](../deploy/docker-compose.override.yml)
и [`../deploy/caddy/Caddyfile`](../deploy/caddy/Caddyfile); развёртывание
целиком — [`../docs/deploy.md`](../docs/deploy.md).

## Проверка

```bash
curl -s http://<station-host>:7700/room/health          # в LAN
curl -s https://<station-domain>/room/health                # снаружи
```

Сообщение и сверку проверять **телом из Python**, а не `curl -d` из Git Bash:
русский текст там превращается в `?????`, и сверка честно отвечает «ничего не
нашёл» — на это уже попадались.

```bash
python - <<'PY'
import json, urllib.parse, urllib.request
body = json.dumps({'text': 'Что это за песня?'}, ensure_ascii=False).encode()
req = urllib.request.Request('http://<station-host>:7700/room/messages', data=body, headers={
    'Content-Type': 'application/json', 'X-Listener-Id': 'probe',
    'X-Listener-Name': urllib.parse.quote('Проверка')})
print(urllib.request.urlopen(req, timeout=15).read().decode())
print(json.load(urllib.request.urlopen(
    'http://<station-host>:7700/room/resolve?q=' + urllib.parse.quote('Кино — Звезда по имени Солнце'))))
PY
```
