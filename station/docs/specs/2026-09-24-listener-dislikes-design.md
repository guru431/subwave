# Дизлайки слушателей и предложения блокировки — дизайн

Дата: 2026-09-24
Статус: **замысел**, к исполнению.

Слушатель отмечает в плеере, что ему не нравится песня или исполнитель целиком. Отметки
копятся в комнате, а на вкладке **Admin → Library → Blocked** владелец видит из них
предложения — что заблокировать — и решает сам, одной кнопкой.

**Контекст, который здесь не повторяется:** комната —
[`station/room/README.md`](../../../station/room/README.md), патч веба —
[`station/docs/web-changes.md`](../web-changes.md), блокировка —
[спека блокировки по жанрам и папкам](2026-09-23-station-genre-folder-blocking-design.md).

## 1. Заказ

Решения владельца от 2026-09-24:

| # | Что |
|---|---|
| 1 | Два вида дизлайка: на песню и на исполнителя |
| 2 | Дизлайк — только сигнал: эфир от него не меняется, блокирует владелец |
| 3 | Песня попадает в предложения с первого дизлайка |
| 4 | Исполнитель попадает и без явного дизлайка, если дизлайкнуты две и больше его песни |
| 5 | Кнопка — на карточке «Сейчас играет» и в каждой строке «Уже прозвучало» |
| 6 | Одна кнопка 👎 с меню из двух пунктов, а не две кнопки |
| 7 | Дизлайки живут в комнате; контроллер не меняется |

## 2. Что показала разведка

Апстрим `subwave` v1.8.0 с обоими нашими патчами.

**Хранилище лайков апстрима для дизлайков не годится.** Сердце на карточке трека пишет в
`state/likes.json` (`broadcast/likes.ts`), и слушатель там — `HMAC(secret, ip)`. А все
внешние слушатели приходят в стек одним адресом: Caddy переписывает `X-Forwarded-*` для
пиров вне `trusted_proxies`, и Apache туда не входит. Посчитать по такому ключу «разных
слушателей» нельзя. У плеера есть свой id слушателя — `web/lib/listener.ts`, по нему уже
работают чат и push.

**Блокировать есть чем.** `POST /library/blocklist` с `{type, trackId}` сам находит по
песне id альбома или артиста через Subsonic. `POST /library/blocklist/check` отвечает
`hitOf` на каждую строку: записи по id, затем по имени артиста, по паре «альбом + артист»,
затем активные правила — поля тегов правило находит по id в библиотеке.

**Окно станции у комнаты уже есть.** `station.window()` читает `/state` контроллера:
текущий трек и до 50 прозвучавших, у каждого `subsonic_id`, `title`, `artist`, `album`.
Скачивание пускает только треки из окна, остальным отвечает 403. Лента «Уже прозвучало» в
плеере строится из того же `/state`.

**Пароль админки** — HTTP Basic: токен `base64(user:pass)` лежит в `localStorage`
(`subwave_admin_auth`), `requireAdmin` контроллера после 10 неудач блокирует адрес на
15 минут. Снаружи Apache пускает `/admin` и `/api/(settings|system|…)` только из
приватных сетей.

**В вебе** есть меню на Radix (`components/ui/dropdown-menu.tsx`) и тосты `sonner` в
классическом скине.

## 3. Решение

### 3.1 Дизлайк

- Вид — `track` («не нравится песня») или `artist` («не нравится исполнитель»).
- Ставится на песню из окна станции — ту, что звучит, или прозвучавшую. `title`, `artist`
  и `album` комната берёт из окна, а не из запроса: произвольную строку дизлайкнуть нельзя.
- Слушатель — `X-Listener-Id`, имя — `X-Listener-Name` (percent-encoded, чистится и
  режется до 40 символов, как в чате). Пустое имя — слушатель не назвался.
- Цель: у `track` — `song_id`, у `artist` — `norm(artist)` из `music/normalize.py`, та же
  нормализация, что у сверки заказа, и файл уже лежит в образе комнаты. Дизлайк
  исполнителя у трека без исполнителя — отказ.
- Одна отметка слушателя на цель. Повторная постановка уже стоящей отметки — не новый
  дизлайк: время записи не меняется. Снятие и новая постановка — новый дизлайк с новым
  временем.
- Каждое нажатие переписывает имя во всех записях слушателя: назвался позже — владелец
  увидит имя.
- Хранится бессрочно, без чистки по возрасту: это вкусы, а не лента.
- В эфире не меняется ничего.

### 3.2 Предложения

Считаются при запросе и не хранятся.

- **Трек** — любая песня хотя бы с одним дизлайком `track`.
- **Исполнитель** — ключ `norm(artist)`, у которого есть хотя бы один дизлайк `artist`
  **или** дизлайки `track` у двух и больше разных песен. Вклад в строку дают и те, и
  другие. Одна дизлайкнутая песня без явного дизлайка — не предложение исполнителя.
- В строке: сколько разных слушателей внесли вклад и их имена; у исполнителя — ещё
  сколько слушателей дизлайкнули его явно и сколько разных песен дизлайкнуто; время
  последнего вклада; «представитель» — `song_id` самой свежей записи (по нему контроллер
  найдёт, что блокировать) и подписи из неё же.
- Порядок в группе: больше слушателей — выше, при равенстве — свежее.
- **Решение владельца** (`keep` или `blocked`) запоминается со временем. Строка скрыта,
  пока нет вклада новее решения. Дизлайки при этом не стираются: вернувшаяся строка
  покажет честный счёт.

### 3.3 Хранение

`room.db`, рядом с лентой; таблицы заводит `CREATE TABLE IF NOT EXISTS` при старте.

```sql
CREATE TABLE IF NOT EXISTS dislikes (
  listener_id TEXT NOT NULL,
  name        TEXT NOT NULL,   -- '' — слушатель не назвался
  kind        TEXT NOT NULL,   -- 'track' | 'artist'
  target      TEXT NOT NULL,   -- song_id у track, norm(artist) у artist
  artist_key  TEXT NOT NULL,   -- norm(artist); '' у трека без исполнителя
  song_id     TEXT NOT NULL,   -- песня, с которой поставлена отметка
  title       TEXT NOT NULL,
  artist      TEXT NOT NULL,
  album       TEXT NOT NULL,
  at          TEXT NOT NULL,
  PRIMARY KEY (listener_id, kind, target)
);
CREATE INDEX IF NOT EXISTS dislikes_artist ON dislikes (artist_key);

CREATE TABLE IF NOT EXISTS dislike_decisions (
  kind       TEXT NOT NULL,
  target     TEXT NOT NULL,
  action     TEXT NOT NULL,    -- 'keep' | 'blocked'
  decided_at TEXT NOT NULL,
  PRIMARY KEY (kind, target)
);
```

Альбом хранится ради отсева (§3.6): без него трек из заблокированного альбома висел бы в
предложениях. Потолок таблицы — 5000 записей: адрес открыт наружу, как у подписок push.
Время передаётся параметром `now`, а не берётся изнутри — правило проекта.

### 3.4 Запросы комнаты

Снаружи — под `/room/`, как весь путь комнаты; префикс снимает Caddy.

**Слушателю** (без пароля):

| Метод | Что |
|---|---|
| `GET /dislikes` | отметки этого слушателя по песням окна: `{"marks": {"<songId>": {"track": bool, "artist": bool}}}`; песни без отметок не перечисляются |
| `POST /dislikes` | `{songId, kind, on}` — поставить (`on: true`) или снять отметку; ответ — `{songId, track, artist}` для этой песни |

Снятие тоже сверяется с окном: без окна не узнать исполнителя песни, а значит и цель
дизлайка `artist`.

Отказы: 400 — нет `X-Listener-Id`, `kind` не `track`/`artist`, нет `songId`, `on` не
булево, дизлайк исполнителя у трека без исполнителя; 403 — песни нет в окне; 413 — тело
больше 8 КБ; 429 — новая отметка при 5000 записях (снятие работает всегда); 502 — станция
не ответила.

**Владельцу:**

| Метод | Что |
|---|---|
| `GET /admin/dislikes` | `{"artists": [...], "tracks": [...]}` — видимые предложения §3.2 |
| `POST /admin/dislikes/decide` | `{kind, key, action}` — записать решение; 404, если у цели нет дизлайков |

Строка предложения: `kind`, `key` (цель), `songId`, `title`, `artist`, `album`,
`listeners` — `[{name, tag}]`, где `tag` — первые 4 символа id слушателя (по нему
карточка различает неназвавшихся), у исполнителя — `explicit` и `songs`, `lastAt`.

**Пароль проверяет контроллер.** Комната пересылает заголовок `Authorization` в
`GET /settings` контроллера — тем же запросом админка проверяет вход. Ответ 200 —
владелец; 401 — комната отвечает 401; 429 (блокировка после 10 неудач) — 429 с
`Retry-After`; прочее и недоступный контроллер — 502. Без заголовка — 401 сразу, в
контроллер не ходим. Своей копии пароля у комнаты нет, и перебрать его через комнату не
выйдет — блокировка у контроллера та же. `WWW-Authenticate` комната не шлёт: иначе
браузер поднял бы поверх админки своё окно входа.

### 3.5 Плеер

- **Кнопка** — значок `ThumbsDown` рядом с сердцем и стрелкой скачивания: на карточке
  «Сейчас играет» между ними (`♡ 👎 ⤓`), в строке «Уже прозвучало» — перед скачиванием.
  Треки без `subsonic_id` (джинглы, реплики) кнопки не получают.
- **Меню** — Radix, два пункта с галочками: «Не нравится песня» и «Не нравится
  исполнитель»; у трека без исполнителя второй неактивен. Значок подсвечен, если у песни
  есть отметка этого слушателя; отметка исполнителя подсвечивает все его песни на экране.
- **Состояние** — провайдер в `ClassicSkin`: `GET /room/dislikes` при смене трека
  (текущего или головы истории) и после каждого нажатия. Кнопки читают контекст, поэтому
  сетевое состояние не перерисовывает `CenterStage` под `memo` — по той же причине сердце
  живёт в своём хуке. Пока запрос идёт, пункты меню неактивны.
- **Отклик — тостом**: эфир не меняется, и слушатель должен понять, что это сигнал.
  Поставлено — «Отмечено: не нравится „<название или исполнитель>“. Решение за
  владельцем станции»; снято — «Отметка снята»; 403 — «Песня уже уехала из ленты»; 502 —
  «Станция не ответила, попробуйте позже»; 429 — «Отметок слишком много»; прочее — «Не
  получилось отметить».
- Правится только классический скин, как с чатом и скачиванием.

| Файл | Что |
|---|---|
| `web/lib/roomDislikes.ts` + тест | запросы в комнату с заголовками слушателя, разбор ответа, текст ошибки по коду — без React |
| `web/components/skins/classic/DislikesContext.tsx` | провайдер и хук отметок |
| `web/components/skins/classic/DislikeMenu.tsx` | кнопка и меню |
| `ClassicSkin.tsx`, `CenterStage.tsx`, `drawers/TimelineDrawer.tsx` | подключение |

### 3.6 Карточка Dislikes

Вкладка **Admin → Library → Blocked**, первой — выше правил: это входящие решения.
Подписи английские, как во всей админке.

- Две группы — Artists, затем Tracks. Строка: метка `artist`/`track` (как в Never play),
  название и исполнитель; у исполнителя причина — «disliked by Маша, Дима · 3 songs
  disliked»; неназвавшийся — `anon·a1b2`; дата последнего вклада; кнопки **Block** и
  **Keep**. В заголовке — сколько ждёт решения; пусто — «No dislikes to review —
  listeners mark tracks and artists with 👎 in the player».
- **Block**: `POST /api/library/blocklist {type, trackId: songId}`, успех — 201 или 409
  («уже заблокировано»); затем `decide(blocked)`; затем, как после блокировки из строки
  библиотеки, перечитываются Never play и пометки строк на других вкладках
  (`restampBlockMarks`).
- **Keep**: `decide(keep)`.
- **Отсев заблокированного** — `POST /api/library/blocklist/check`: трек — строкой
  `{id: songId, artist, album}`, исполнитель — `{id: "artist:" + key, artist}`, **только
  имя**. С настоящим `songId` ответ «заблокирован» про одну песню — записью трека или
  правилом по жанру и папке — выдал бы себя за блок всего исполнителя. Заблокированное
  чем угодно не показывается.
- Запросы в комнату — с тем же токеном, что у `adminFetch`, включая чтение из
  `localStorage` до гидратации. Комната недоступна — ошибка в карточке, остальная вкладка
  работает.

| Файл | Что |
|---|---|
| `web/lib/dislikeSuggestions.ts` + тест | строки для `check`, отсев по ответу, строка причины — без React |
| `web/components/admin/library/DislikesCard.tsx` | карточка |
| `web/components/admin/library/tabs/BlockedTabContainer.tsx` | карточка встаёт первой |

### 3.7 Apache

`/room/admin` — в правило «только из приватных сетей», рядом с `/admin`:

```apache
<LocationMatch "^/(admin|room/admin|api/(settings|system|debug|doctor|backup|mcp))">
```

Прямой вход `http://<station-host>:7700` этого правила не видит — там остаётся пароль.

## 4. Отказы

| Ситуация | Поведение |
|---|---|
| Контроллер не отвечает | `/dislikes` — 502 (нет окна), плеер: «Станция не ответила»; `/admin/*` — 502 (пароль нечем проверить), карточка показывает ошибку |
| Песня уехала из окна между отрисовкой и нажатием | 403, «Песня уже уехала из ленты» |
| Первая минута после смены трека | карточка плеера может показывать запись, которой ещё нет в окне, — тот же 403; ограничение общее со скачиванием |
| Комната не отвечает | плеер: «Не получилось отметить»; карточка — ошибка, остальная вкладка работает |
| 5000 записей | новые отметки — 429, снятие работает |
| Блок прошёл, `decide` упал | строку всё равно прячет отсев; решения нет — после разблокировки строка вернётся |
| Откат комнаты на прежний образ | новых таблиц он не видит; данные остаются в `room.db` до повторной выкатки |
| Откат веба | кнопок и карточки нет; комната работает как прежде |

## 5. Проверка

- **Комната, быстрый набор** — `tests/test_room_dislikes.py`; окно станции и контроллер —
  заглушки, время — параметром:
  - хранилище: постановка и снятие, повтор не считается, имя переписывается во всех
    записях слушателя, потолок;
  - сводка: трек с первого дизлайка; исполнитель — по явному дизлайку и по двум песням,
    одна песня — не предложение; `keep` и `blocked` прячут до нового вклада, повторная
    постановка стоящей отметки — не новый вклад; порядок;
  - запросы: 400/403/413/429/502; `/admin/*` — 200 при «да» контроллера, 401 без
    `WWW-Authenticate`, 429 с `Retry-After`, 502 при недоступном; `decide` без
    дизлайков — 404.
- **Веб** — `npx tsx web/lib/roomDislikes.test.ts` и
  `npx tsx web/lib/dislikeSuggestions.test.ts` в контейнере на Debian, как тесты чата;
  `eslint` и `tsc --noEmit` по изменённым файлам: весь `npm run lint` красный и до правки
  из-за трёх старых ошибок патча ([README l10n](../web-changes.md)).
- **Живая приёмка** — пробным id слушателя, его записи потом снимаются:
  - дизлайк текущей песни → тост → строка в карточке с именем;
  - две песни одного исполнителя → исполнитель с «2 songs»;
  - Block → запись в Never play, строка ушла, после разблокировки не вернулась;
  - Keep → строка ушла, новый дизлайк → вернулась;
  - снятие отметки уменьшает счёт;
  - `https://<station-domain>/room/admin/dislikes` снаружи (или подменой списка сетей, как при
    первой настройке) — 403, в LAN без пароля — 401, с паролем — 200.

## 6. Выкатка

Прежний образ перед каждой сборкой сохраняется под отдельным тегом.

1. Apache: правка `apache-fm.conf` → копия в `<deploy-dir>/deploy/` → `configtest` →
   `graceful`. Первым — чтобы `/room/admin` ни минуты не смотрел в интернет без второго
   рубежа.
2. Комната: сборка `subwave-room:1` → `compose up -d room`.
3. Веб: правка в клоне → пересборка `ru-web.patch` через `git add -A` → наложение на
   чистый клон → сборка `subwave-web:1.8.0-ru` → `compose up -d web`.
4. Живая приёмка (§5).
5. Документация: README комнаты (поверхность, таблицы, пароль через контроллер), README
   `l10n` (кнопка, карточка, число файлов патча), таблица состояния README станции,
   `CLAUDE.md` — грабли, если всплывут.

## 7. Что не входит

- Влияние дизлайков на эфир и на выбор ведущего.
- Остальные пять скинов плеера.
- Уведомление владельцу о новых дизлайках.
- Дизлайк альбома.
- Просмотр и чистка всех дизлайков в админке — только предложения.

## 8. Риски

- **Патч `web` растёт** — ещё 5–6 файлов, и правки в местах, которые трогает апстрим
  (`CenterStage`, `TimelineDrawer`, вкладка Blocked). Каждое обновление апстрима — больше
  конфликтов.
- **id слушателя подделывается.** Подделка даёт лишние предложения, но не блокировку —
  решает владелец. Объём ограничен потолком таблицы.
- **Комната склеивает имена строже контроллера.** `norm()` снимает пунктуацию и склеивает
  ё/е, а блок-лист сравнивает имена лишь без регистра и лишних пробелов. Если два
  написания склеились в одно предложение, Block заблокирует артиста песни-представителя, а
  второе написание в эфире останется.
