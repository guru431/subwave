# Изменения форка в вебе: плеер и админка

Что форк меняет в `web/` апстрима subwave и почему. Ветка `main` — апстрим `v1.17.0` и
поверх него наши коммиты `feat|fix(web): …`, по коммиту на фичу. Каждый раздел ниже —
одна фича: заголовок раздела совпадает с заголовком её коммита без префикса, порядок —
порядок коммитов, первая строка — номер фичи и коммит. Как фичи переехали с v1.8.0 и
что при этом переписано — таблица вердиктов [port-1.17.md](port-1.17.md) (строки
W01–W14). Изменения контроллера — [controller-changes.md](controller-changes.md),
комната (`/room/…`) — [room/README.md](../room/README.md).

**Объём правки** считается командой, а не берётся из текста:
`git diff --stat v1.17.0 main -- web` (на 2026-10-05 — 59 файлов).

**Правится один скин из шести.** У плеера шесть скинов (`classic`, `unit`, `drift`,
`subamp`, `tty`, `platter` — `web/components/skins/`), и ящики, кнопки и подписи у
каждого свои. Станция работает на `classic`, поэтому перевод, чат, скачивание и
дизлайки сделаны только в нём: размножать их на скины, которыми никто не пользуется,
значит вшестеро увеличить правку и число конфликтов при обновлении апстрима. Общие
части плеера (`PlayerCore`, `usePlayer`, `useMediaSession`, `useStationFeed`,
`lib/poll.ts`, `lib/hooks.ts`) правятся для всех: экран блокировки, выключение звука на
iOS и фон на Android работают в любом скине.

**Админка (`/admin`) не переводится.** Это отдельный слой в несколько сотен строк,
которым пользуется один человек и только при настройке; новые карточки вкладки
Blocked (W12, W13) подписаны по-английски, как всё вокруг.

**Автоматических тестов у веба апстрима нет** — ни раннера, ни `npm test`. Поэтому всё
решающее в наших фичах вынесено в чистые модули без React и сети (`web/lib/*.ts`) и
проверяется отдельными скриптами `web/lib/<имя>.test.ts` (тот же приём, что у
апстримного `audienceStats.test.ts`: `assert`, ✓/✗, ненулевой код выхода). Остальное —
линтер, typecheck и проверка на живой станции; где что — в «Чем проверено» каждого
раздела, как запускать — в разделе «Линтер, typecheck и тесты». Тесты, линтер и
typecheck пройдены при переносе на v1.17 (0 ошибок); проверки на живой станции —
приёмка выкатки образа `1.17.0-ru` (на v1.8 эти фичи работали в эфире).

## Русский интерфейс плеера

`W01` · `a3b4d54e`

У subwave **нет i18n** — ни каталога переводов, ни языковой настройки:
`settings.locale` объявлена как `'en-GB' | 'en-US'` и управляет только тем, будет ли
время 24-часовым или с AM/PM. Строки интерфейса лежат прямо в компонентах React,
поэтому русский интерфейс — это правка самих компонентов и свой образ `web`
(раздел «Сборка»).

Переведена плеерная страница целиком: шапка, карточка трека, нижняя панель, оверлей
включения, все четыре ящика апстрима (лента, студия, заказ, расписание), палитра
команд, список сочетаний клавиш и окно пароля закрытой станции. Файлы —
`web/components/skins/classic/` (`CenterStage`, `ClassicSkin`, `CommandPalette`,
`DjThinkingLine`, `DotRail`, `ShortcutsDialog`, `TopBar`, `TransportBar`,
`TuneInOverlay`, `drawers/{Booth,Request,Schedule,Timeline}Drawer`) и
[StationGate.tsx](../../web/components/player/StationGate.tsx).

При переносе на v1.17 новых английских строк в классическом скине нашлась одна пара —
«More/Less» раскрытия темы шоу (v1.14), стала «Ещё/Свернуть». Заодно дописано
пропущенное на v1.8: расписание («Сейчас · до …», «· с …», «без ведущего», два
пояснения), шаблонный ответ ящика заказа «Принято — передаём в студию», строка мета в
эфире студии («заказ:», «источник:»). Подсказки-заказы ящика («more like this» и
другие) не переводятся: это текст заказа, который разбирает контроллер.

После переноса закрыты последние английские строки страницы: «ищем ваш трек…» и «В
очереди: №n» в карточке заказа, «↦ дальше» на сцене, пустая лента и «↳ заказ: …» в
ней, описание сайта (`DESCRIPTION` в [layout.tsx](../../web/app/layout.tsx) — `<meta
description>`, Open Graph и JSON-LD). Время в «Уже прозвучало» — «5 мин назад», у
индикатора сигнала подсказка и `aria-label` — «1 слушатель / 2 слушателя / 5
слушателей». `relTime` из `lib/format.ts` общий для всех скинов и отдаёт `5m`, поэтому
переводится его ответ в точке показа (`ruAgo`), а не он сам; число склоняет `ruPlural`
(оба — в `ru.ts`, ниже).

Не переводится намеренно:

| Что | Почему |
|---|---|
| Названия треков, исполнителей, альбомов | данные коллекции: `Depeche Mode` остаётся `Depeche Mode` |
| Имена клавиш (`Enter`, `Space`, `PageUp`) | подписи физических клавиш, а не текст интерфейса |
| `SUB/WAVE` на прочих страницах апстрима | название продукта; на странице плеера его вытесняют имя станции из настройки `station` и запасное «AI радио» (W04) |
| Жанр, BPM, тональность | теги файлов коллекции |
| Названия и описания тем в диалоге «Оформление» | данные станции (`GET /themes`), как названия треков; у встроенных тем апстрима — английские |

### Строки страницы плеера вне скина

Обещание «плеерная страница целиком» держалось только внутри `classic`, а на странице
есть и общие компоненты:

| Где | Что было по-английски | Как переведено |
|---|---|---|
| [ThemeSwitcher.tsx](../../web/components/ThemeSwitcher.tsx) — значок палитры в шапке | весь диалог «Appearance»: тема, «Use station default», «Lite mode», крестик | таблица строк `COPY` по `variant`: `player` — по-русски, `admin` — прежние английские. Тот же диалог стоит в шапке админки (`AdminShell`, `variant="admin"`), а админка не переводится — её он не задевает |
| [sheet.tsx](../../web/components/ui/sheet.tsx) | `aria-label="Close"` у крестика каждого ящика | «Закрыть»; `Sheet` использует только `ClassicSkin` |
| [useTuneInGate.ts](../../web/components/player/useTuneInGate.ts) | тост автоотключения через 8 ч без действий | «Эфир выключен — вас долго не было…»; хук общий для всех скинов |
| [PlayerShell.tsx](../../web/components/player/PlayerShell.tsx) | тосты клавиш `S`/`T` («Skin: …», «Theme: …») | «Вид плеера: …», «Тема: …» |

**На странице плеера — только `classic`.** Тот же диалог и клавиша `S` уводили слушателя
в один из пяти непереведённых скинов — без чата, 👎, скачивания и ползунка, — и выбор
запоминался в `localStorage`. Теперь `PlayerShell` вне витрины отдаёт в `SkinSelection`
один `classic` (`PAGE_SKINS`): раздел «Вид плеера» в диалоге скрывается по условию
апстрима `skins.length > 1`, `S` при одном скине ничего не делает и пропадает из
списка сочетаний (`ShortcutsDialog`), а сохранённый раньше выбор чужого скина при
загрузке **стирается** — не просто не применяется: иначе предварительный скрипт
`SKIN_INIT_SCRIPT` прятал бы оболочку до гидратации на каждой загрузке. Настройка скина
станции из админки (`ui.skin`) по-прежнему действует — это решение владельца, а не
слушателя; витрины (`contained`, лендинг апстрима) показывают весь реестр.

**Чем проверено** (эта часть). Линтер и typecheck веба. После подъёма образа — диалог
«Оформление» на странице плеера по-русски и без раздела «Вид плеера», `S` ничего не
делает, в `/admin` тот же диалог по-английски; браузер, где раньше был выбран другой
скин, открывает `classic`. Автотеста нет: это разметка и `localStorage`, а DOM-окружения
для тестов у веба нет.

### Словарь для данных станции — `web/lib/ru.ts`

Часть английских слов на экране приходит **от контроллера**: время суток (`afternoon`),
настрой часа (`sustained energy`), погода (`cloudy`), настроения и уровень энергии трека.
Переводить их в контроллере нельзя — это **ключи**: по ним идут `settings.moodSchedule`,
`settings.weatherMoods`, подбор треков и промпты ведущего. Поэтому словарь
[ru.ts](../../web/lib/ru.ts) применяется **в точке показа**, а данные остаются
нетронутыми: строка контекста в шапке ([tagline.ts](../../web/lib/tagline.ts) — время
суток, настрой, погода, настроение праздника) и карточка трека (`CenterStage` —
настроения, энергия, альбом).

Незнакомое значение возвращается как есть: новый вариант в апстриме должен проявиться
английским словом, а не пропасть с экрана. Там же гасится `[Unknown Album]` — заглушка
Navidrome вместо пустого тега, а не название альбома.

Там же два помощника для подписей с числом: `ruPlural` (форма слова: 1 слушатель, 2
слушателя, 5 и 11 слушателей) с обёрткой `ruListeners` и `ruAgo` — ответ `relTime`
(`5m`) в виде «5 мин назад»; незнакомый вид отдаётся с «назад», без потери числа.

**Чем проверено.** `npx tsx web/lib/ru.test.ts` (склонение числа слушателей, «назад»);
линтер и typecheck веба; на живой станции — английских подписей на странице плеера нет,
кроме перечисленных в таблице выше. Словарь значений станции юнит-тестов не имеет.

## Ящик чата

`W02` · `482246ef`

Пятый ящик плеера — чат с комнатой станции:
[ChatDrawer.tsx](../../web/components/skins/classic/drawers/ChatDrawer.tsx), опрос —
[useRoomFeed.ts](../../web/hooks/useRoomFeed.ts), слепок слушателя —
[listener.ts](../../web/lib/listener.ts) (`id`, имя, докуда прочитан чат и согласие на
уведомления; один ключ `localStorage` — `subwave.listener`). Коммит несёт и модули
правил ленты и уведомлений (`lib/roomRules.ts`, `lib/roomNotify.ts`, `lib/roomPush.ts`),
потому что их импортирует сам ящик; уведомления разобраны в следующем разделе.

**Подключение — четыре точки, пропуск любой даёт ящик, который не открыть:** тип
`PlayerDrawer` и пункт палитры в `CommandPalette.tsx`, заголовок и клавиша `5` в
`ClassicSkin.tsx`, точка на рейке в `DotRail.tsx`, строка в `ShortcutsDialog.tsx`.
Клавиша `5` у апстрима v1.17 свободна — сверять при каждом обновлении.

**Ящик ходит не в контроллер, а в комнату** (`/room/*`): у контроллера нет понятия
чата, а слушателю нужен путь без админского пароля. Маршрут `/room/*` — в нашем
[Caddyfile](../deploy/caddy/Caddyfile); поверхность комнаты, её лимиты и разбор текста —
[room/README.md](../room/README.md), здесь не пересказываются.

- **Опрос.** Открытый ящик спрашивает `GET /room/messages?since=` раз в 5 с,
  закрытый — раз в 30 с (ради счётчика на точке); скрытая вкладка — только пока играет
  эфир (флаг ссылкой `keepAliveWhenHidden`, тот же приём, что у ленты станции в W07).
- **Замок на опросе** (`busyRef`): опрос зовут двое — интервал и отправка, и без замка
  оба прочитали бы один `since`, получили одну пачку и дописали её дважды.
- **Два курсора:** докуда **скачано** (`since`) и докуда **прочитано** человеком
  (`lastSeenId`). Скачать можно при закрытом ящике, прочитать — нет. Отправка двигает
  «прочитано» по номеру из ответа комнаты, а не по приходу своего сообщения следующим
  опросом — иначе закрытый сразу после отправки ящик счёл бы свою реплику непрочитанной.
- **Личность — заголовками.** `X-Listener-Id` нужен комнате для частотного лимита:
  снаружи все слушатели приходят в стек одним адресом. Имя в `X-Listener-Name` едет
  **percent-encoded**: HTTP-заголовки по RFC 7230 — latin-1, кириллицу в них браузер не
  закодирует. Длины — те же, что у заказа: имя 40, текст 280.
- **Хранилище запрещено** (приватное окно) — плеер не ломается: чат работает до
  перезагрузки под случайным `id`. Этот `id` — **один на вкладку**: `listener()`
  запоминает запасной в переменной модуля. Прежде `catch` выдавал новый на каждый
  вызов, и каждый запрос приходил в комнату от нового слушателя — 👎 не держались
  (комната отдаёт отметки по `X-Listener-Id`), частотный лимит считал каждый запрос
  первым. Имя, «прочитано» и согласие без хранилища по-прежнему не запоминаются.

**Лента ящика — три источника:** сообщения комнаты, ответы ведущего и строки «сейчас
играет …». Склейку делает скин (`mergeFeed` в [roomRules.ts](../../web/lib/roomRules.ts)),
последние 100 строк. Сортировка — по времени, стабильная, **без** тай-брейка по ключу:
комната отдаёт `at` с точностью до секунды, и строковое сравнение ключей `m<id>` ставило
`m100` перед `m99` — ответ раньше вопроса.

**«Ведущий ответил» опознаётся точно, а не по тексту.** Контроллер кладёт в каждую
произнесённую реплику слаг навыка (`broadcast/queue.ts::onSpoken`, `turn.kind ===
'chat'`), а `useStationFeed` отдаёт ленту уже отфильтрованной по слышимости — реплика
попадает в чат ровно тогда, когда её слышно здесь, а не когда контроллер её сочинил.
Первая пришедшая лента — история: она видна, но молчит. Взводится она на первой
**непустой** ленте, а не на первой с репликами `chat`: иначе первый настоящий ответ за
сессию сошёл бы за историю и прозвучал молча.

**Лента — `role="log"`, и вниз она тянет не всегда.** Новые сообщения, ответы
ведущего и строки «сейчас играет» скринридер объявляет сам (`role="log"
aria-live="polite"` на прокручиваемом контейнере), не перебивая. Прежде любое изменение
ленты, включая строку «сейчас играет» раз в трек, прокручивало ящик вниз и сбивало с
места того, кто листает историю. Теперь вниз — только если до изменения читатель стоял
у дна (меньше 40 px, мерится на прокрутке: новая строка удлиняет ленту без события
прокрутки) или только что отправил своё сообщение (флаг из `submit`, снимается
ближайшим изменением ленты). Открытый ящик по-прежнему встаёт на последнее.

**Служебные строки живут в памяти вкладки.** «Сейчас играет» и реплики ведущего в
комнату не пишутся и перезагрузку не переживают — в отличие от сообщений слушателей.
Писать их в комнату нельзя: навык `chat` читает `/unread` и зачитал бы в эфире
собственные реплики как сообщения слушателей. Смена трека в ленте — контекст
разговора, ни тоста, ни уведомления она не даёт.

**Чем проверено.** `npx tsx web/lib/roomRules.test.ts` — счёт непрочитанного, «своё и
чужое», отбор и опознание реплик ведущего, порядок склейки (в том числе сообщения одной
секунды); `npx tsx web/lib/listener.test.ts` — без хранилища `id` один на вкладку;
typecheck веба; на живой станции — сообщение в чате и ответ ведущего.

## Уведомления чата (Web Push)

`W03` · `c5c7d6a0` · [спека](specs/2026-09-22-chat-notifications-design.md)

**Непрочитанное показывает рейка точек.** У апстрима она уже умеет счётчик
(`counts`), но подставляет `counts?.[k] ?? 0` — до этой правки на точке «Чат» висел
вечный `0`; теперь `ClassicSkin` отдаёт туда `room.unread`.

**Что звучит громко.** Каждое чужое сообщение и каждая реплика ведущего с
`kind === 'chat'` (решение владельца от 2026-09-23; до того громким было только
упоминание имени, и сообщения других слушателей молча капали в счётчик). Своё — нет:
своё опознаётся по номеру из ответа комнаты либо по тому же имени в свёрнутой форме
(регистр, `ё`/`е`, латинская диакритика не в счёт) — так не звенит и своё сообщение с
другого устройства. Из пачки звенит **последнее** сообщение, а не каждое: после
переподключения пачка бывает длинной. Первая пачка после загрузки — история, она молчит.
Правила — `fromOthers`/`djChatReplies` в [roomRules.ts](../../web/lib/roomRules.ts).

**Как звучит.** Закрытый ящик — тост `notify.chat` (8 с, кнопка «Открыть»,
[notify.ts](../../web/lib/notify.ts)). Скрытая вкладка — системное уведомление
(`showHidden` в [roomNotify.ts](../../web/lib/roomNotify.ts)): на открытой своё дело
делает тост, два уведомления об одном — шум. Показ требует **и** разрешения браузера,
**и** согласия слушателя: снятая в ящике галочка обязана выключать показ, а не только
рисоваться снятой.

**Переключатель «Уведомлять о важном»** — в ящике. Разрешение браузер даёт только по
жесту, поэтому спрашивается из нажатия, а не при загрузке. Где включать нечего, вместо
переключателя стоит причина — невидимая причина читается как поломка: запрет в
настройках браузера, «на iPhone — только из установленного приложения» (в обычной
вкладке Safari уведомлений нет вовсе), браузер без `Notification`. Решение —
чистая функция `notifyState`.

**Уведомление страницы живёт, пока жива вкладка.** Браузер замораживает скрытую
вкладку, и опрос продолжается только пока играет звук. Поэтому тот же переключатель
оформляет ещё и **Web Push** ([roomPush.ts](../../web/lib/roomPush.ts)): подписку хранит
комната и сама шлёт уведомление, когда вкладка закрыта (что считать важным, комната
решает по тем же правилам — [room/README.md](../room/README.md), раздел «Web Push»).
Согласие одно, способов доставки два:

| Где | Что |
|---|---|
| `ChatDrawer.tsx` | включение переключателя подписывает браузер, выключение отписывает; смена имени обновляет подписку — по имени комната узнаёт автора на его другом устройстве; потерянная подписка — строка «Уведомления отключены — включите заново» |
| `ClassicSkin.tsx` | переподписка на каждом открытии плеера; `?chat=1` в адресе и сообщение `room:open-chat` от service worker открывают чат |
| [sw.js](../../web/public/sw.js) | `push` показывает уведомление, если нет видимой вкладки (на WebKit — всегда, см. ниже); `notificationclick` поднимает открытую вкладку плеера или открывает новую с `/?chat=1` |

- **Подписка на прежний ключ комнаты мертва** — push-сервис отвергнет подпись сервера.
  `enablePush` сверяет ключ подписки с `GET /room/push/key` (`sameKey`), снимает
  устаревшую и заводит заново. Браузер, не сообщающий ключ подписки, — повод её не
  трогать. Ключ на стороне комнаты пересоздавать нельзя — [station-pitfalls.md](station-pitfalls.md), «Комната».
- **Недоступный push — не поломка:** функции `roomPush.ts` молча возвращают «не вышло»,
  уведомления страницы работают как прежде; не дошедшую отписку комната забудет сама по
  первому 410 от push-сервиса.
- **Тег уведомления у страницы и у push один — `subwave-chat`:** на свёрнутой живой
  вкладке пришли бы оба, второе заменяет первое, а не встаёт рядом.
- **Страничное `new Notification()` на Android Chrome не работает вовсе** (там разрешено
  только `registration.showNotification`), так что на Android уведомления о важном
  приходят только через push.
- **На WebKit push без уведомления — «тихий», и за несколько тихих подписку снимают.**
  Комната шлёт push на каждое чужое сообщение, а `sw.js` при видимом окне молчал
  (там скажет тост) — на iPhone с открытым приложением подписка отзывалась после
  серии сообщений. Поэтому на WebKit `push` вызывает `showNotification` всегда, с тем
  же тегом `subwave-chat`, и при видимом окне сразу закрывает его
  (`getNotifications({tag})` → `close()`). WebKit узнаётся по строке агента (`isWebKit`
  в `sw.js`): `AppleWebKit/` без `Chrome/`/`Chromium/`/`Edg/` — так в него попадают
  Safari и все браузеры iOS, а Chromium-браузеры нет; `Safari/` признаком не годится —
  у установленного на iPhone приложения его в строке нет. Chrome и Firefox видимую
  вкладку от тихого push освобождают, у них поведение прежнее.
- **Потерянная подписка видна в ящике.** Переподписка при открытии плеера идёт без
  жеста, и на WebKit она молча не удаётся — галочка «Уведомлять» оставалась включённой
  при мёртвом push. `enablePush` запоминает исход (`pushLost`/`watchPushLost` в
  `roomPush.ts` — состояние модуля, потому что переподписку делает скин, пока ящик
  закрыт), и при неудаче в браузере с push ящик показывает под переключателем кнопку
  «Уведомления отключены — включите заново»: нажатие — тот жест, по которому WebKit
  оформит подписку. Выключенный переключатель потерю снимает; браузер без push
  потерь не знает — у него остаются уведомления страницы.
- **Нажатие на push поднимает вкладку плеера, а не первую вкладку сайта.** Прежний
  `notificationclick` фокусировал первое окно того же origin и слал ему
  `room:open-chat`, которое слушает только плеер: у владельца первой бывала админка
  (`/admin`, `/manual`, `/news`), и чат не открывался. Теперь годится только окно, чей
  путь совпадает с адресом уведомления (`/` из `/?chat=1`); нет такого — новое окно
  `/?chat=1`. Плеер на `/listen` под это не попадает: откроется ещё одно окно, зато с
  чатом.

`sw.js` апстрима v1.17 принял обработчики `push`/`notificationclick` без правок.
`roomPush.test.ts` не проходил typecheck v1.17 (`other[64] ^= 1` при
`noUncheckedIndexedAccess`) — исправлено коммитом
`fix(web): линтер и typecheck веба на v1.17 — 0 ошибок` (`bfbe6cf6`).

**Чем проверено.** `npx tsx web/lib/roomNotify.test.ts` (что показывать вместо
переключателя, включая iOS во вкладке и в установленном приложении),
`npx tsx web/lib/roomPush.test.ts` (разбор ключа сервера по примеру RFC 8291,
опознание подписки на прежний ключ, потеря подписки и её снятие),

WebKit при видимом окне уведомление показано и закрыто, на прочих — нет; нажатие
поднимает вкладку плеера, а не админку, без неё открывает `/?chat=1`),

## Ползунок громкости

`W05` · `2bf76708`

У апстрима громкость — круглая ручка, и отзывается она **только на вертикальное
протягивание** дальше мёртвой зоны в 4 px (`KNOB_DRAG_DEADZONE_PX`). Вбок и тапом —
ничего, отчего она читается как сломанная. В
[TransportBar.tsx](../../web/components/skins/classic/TransportBar.tsx) она заменена
нативным `input[type=range]`: перетаскивание в привычную сторону, клик по дорожке,
клавиатура и озвучивание для скринридера достаются даром. Цвет станции —
утилитой `accent-[var(--accent)]`: на v1.8 стоял `style={{ accentColor }}`, а инлайн-стили
линтер апстрима запрещает (`react/forbid-dom-props`) — исправлено при переносе. Колонки
нижней панели поджаты под ширину телефона (`minmax(0,1fr)`, меньшие отступы), чтобы
ползунок помещался.

**Up/Down плеер слушает глобально** (`PlayerApp`, независимо от фокуса). Нативный
ползунок обработал бы их ещё раз, и шаг удвоился бы, поэтому `onKeyDown` гасит эти две
клавиши; Left/Right, Home/End и PageUp/PageDown остаются его собственными.

**Уровень на iOS не регулируется — но выключение звука работает.** Apple делает
`HTMLMediaElement.volume` доступным только для чтения на уровне системы (любой браузер
на iOS внутри — Safari), а обход через Web Audio апстрим пробовал и отказался: в
установленном PWA он игнорируется и ломает управление с экрана блокировки (#298).
Поэтому на iOS вместо регулятора — приглушённый неактивный ползунок: на касание не
реагирует, доступным не притворяется, VoiceOver объясняет, что уровень задаётся
кнопками устройства.

А `muted` — **отдельный флаг элемента, и его iOS слушает.** Апстрим выключал звук
«громкостью 0» (`usePlayer.toggleMute`), на iOS это не делало ничего, и кнопку в ветке
iOS у него просто убрали. Теперь [usePlayer.ts](../../web/hooks/usePlayer.ts) зеркалит
нулевую громкость в `el.muted` — там, где присваивает `volume`, и в `tune()`/`reconnect()`,
где пересоздаётся источник, — а кнопка стоит на обеих ветках. На остальных платформах
`volume = 0` и `muted = true` дают одно и то же.

**На iOS выключенный звук не переживает перезапуск.** Громкость сохраняется в
`localStorage` и восстанавливается при загрузке (апстрим, #783), в том числе 0. После
зеркала в `el.muted` звук, выключенный на iPhone, оставался выключенным и после
перезапуска плеера, а выйти из этого было нечем, кроме кнопки: аппаратные кнопки
громкости `muted` не снимают, ползунок на iOS неактивен. Поэтому
`loadVolumePref({ ios })` в [volume.ts](../../web/lib/volume.ts) на iOS читает
сохранённый 0 как «ничего не сохранено»: плеер стартует со звуком, и следующая запись
затирает 0. Ненулевой уровень и все прочие платформы — как у апстрима: на компьютере
выключенный звук по-прежнему помнится.

**Неактивный ползунок на iOS показывает выключение звука:** `value` — `muted ? 0 : 100`
и `aria-valuetext` «звук выключен», пока звук выключен. Раньше он стоял на 100% и при
выключенном звуке.

Стили `.fz-knob*` в `globals.css` после этого никем не используются, но не удаляются:
чужой мёртвый код — не повод раздувать правку и конфликты.

**Чем проверено.** Линтер и typecheck веба; `npx tsx web/lib/volume.test.ts` (на iOS 0 не
восстанавливается, ненулевой уровень и прочие платформы — как раньше); на живой станции
— ползунок и выключение звука (на iPhone — владельцем: выключить звук, закрыть и снова
открыть плеер — звук есть, ползунок при выключенном звуке стоит на нуле).

## Установка как приложение

`W06` · `cd95f7db`

Причин было две, и первая — настоящая поломка.

### 1. Chrome не видел манифест вовсе

Все критерии установимости по отдельности выполнялись: HTTPS, манифест отдаётся с
`application/manifest+json`, иконки 192/512 — настоящие PNG заявленных размеров,
service worker с обработчиком `fetch` регистрируется на корневой scope. А браузер
считал, что манифеста **нет**: `Page.getInstallabilityErrors` отвечал `no-manifest`,
`Page.getAppManifest` — пустым адресом и 0 байт. При этом в той же вкладке
`document.querySelector('link[rel=manifest]').href` возвращал адрес, а `fetch()` по
нему — `200 application/manifest+json`.

Причина — **место тега в документе**. Chromium ищет `<link rel="manifest">` только
внутри `<head>`. Страница плеера `force-dynamic` (`app/page.tsx`), и Next стримит весь
блок Metadata API в **тело**: на живой станции `</head>` кончался на байте 7186, а
ссылка Next на манифест лежала на 41881. Туда же уезжали `<title>`, `apple-touch-icon`
и `apple-mobile-web-app-*`. Safari к этому снисходителен и читает их из тела — поэтому
на iPhone станция ставилась, показывала своё имя и иконку, и поломка ничем себя не
выдавала.

Апстрим с этой граблей уже сталкивался, но только на картинке шер-карточки: `og:image`
у него написан руками в `<head>` мимо Metadata API. Манифест чинится тем же способом —
строкой `<link rel="manifest" href="/manifest.webmanifest" />` там же, в
[layout.tsx](../../web/app/layout.tsx). Дубль, который Next по-прежнему кладёт в тело,
безвреден: выигрывает первая ссылка в `<head>`. После правки — `installabilityErrors: []`
и манифест на 984 байта (v1.8).

### 2. Даже установимую страницу Chrome сам не предлагает

**Мини-инфобар Chrome убрал:** событие `beforeinstallprompt` приходит, но само по себе
не показывает ничего; на Android остаётся пункт в меню ⋮, который никто не открывает.
Предложение обязан вывести сам сайт, а у апстрима такого кода нет — слова
`beforeinstallprompt` в его дереве нет и в v1.17.

Поэтому в шапке плеера ([TopBar.tsx](../../web/components/skins/classic/TopBar.tsx))
стоит кнопка [InstallButton.tsx](../../web/components/InstallButton.tsx): событие
перехватывается и переигрывается по нажатию ([install.ts](../../web/lib/install.ts),
[useInstallPrompt.ts](../../web/hooks/useInstallPrompt.ts)). Три тонкости, каждая —
отдельная строка кода:

| Что | Почему |
|---|---|
| Перехват в `<script>` в `layout.tsx` (`INSTALL_INIT_SCRIPT`), до гидратации | на повторном визите worker уже зарегистрирован, и Chrome успевает выстрелить событием, пока React грузится; слушатель в `useEffect` его бы не увидел, и кнопка не появилась бы никогда. На первом визите событие приходит позже, когда оживёт worker, — его ловит слушатель хука |
| Событие одноразовое | браузер отказывается показывать повторно уже показанный промпт; после нажатия ссылка сбрасывается, следующий визит пришлёт новое событие |
| Ветка iOS | API там нет вовсе: кнопка не притворяется, что ставит, а подсказывает маршрут «Поделиться» → «На экран „Домой“» тостом — у станции уже смонтирован один `Toaster` в корне |

Кнопка не рендерится, когда ставить нечего: приложение уже установлено
(`display-mode: standalone`, `window-controls-overlay` или `navigator.standalone` у
Safari — `isStandalone()` в [platform.ts](../../web/lib/platform.ts)) либо браузер
такого не умеет. До монтирования состояние — «установлено», чтобы серверная и первая
клиентская отрисовки совпали; `appinstalled` прячет кнопку сразу. Значок — `Download`,
поэтому у кнопки скачивания трека (W10) другой. Как это выглядит у слушателя на разных
устройствах — [deploy.md](deploy.md), раздел «Как установить и почему браузер сам не
предлагает».

### Проверка установимости

**Проверять самим браузером, а не сверкой критериев.** Список критериев сходился и при
неработающей установке. Авторитетный ответ даёт Chromium — DevTools → Application →
Manifest либо headless по CDP. В прогон **обязательно** входит контроль на заведомо
устанавливаемом стороннем PWA: без него не отличить поломку станции от особенностей
headless, профиля или сети.

1. Браузер без окна с отладочным портом, на чистом профиле (Chrome или Edge — флаги те
   же):

   ```bash
   "<chrome>" --headless=new --remote-debugging-port=9222 \
     --user-data-dir="<tmp>/cdp-profile" about:blank &
   ```

2. Скрипт `pwa-check.mjs` (Node 22+: `fetch` и `WebSocket` встроены, зависимостей нет)
   открывает каждый адрес в своей вкладке, ждёт загрузки и регистрации worker и
   спрашивает браузер:

   ```js
   // node pwa-check.mjs <адрес>...   код 1 — у кого-то есть ошибки установимости
   const PORT = process.env.CDP_PORT || 9222;
   const WAIT_MS = Number(process.env.WAIT_MS || 15000); // загрузка + service worker
   let failed = 0;
   for (const url of process.argv.slice(2)) {
     const tab = await (await fetch(`http://127.0.0.1:${PORT}/json/new?${url}`, { method: 'PUT' })).json();
     const ws = new WebSocket(tab.webSocketDebuggerUrl);
     await new Promise(r => ws.addEventListener('open', r, { once: true }));
     let seq = 0;
     const call = (method, params = {}) => new Promise(resolve => {
       const id = ++seq;
       const on = e => {
         const m = JSON.parse(e.data);
         if (m.id !== id) return;
         ws.removeEventListener('message', on);
         resolve(m.result ?? { error: m.error });
       };
       ws.addEventListener('message', on);
       ws.send(JSON.stringify({ id, method, params }));
     });
     await new Promise(r => setTimeout(r, WAIT_MS));
     const manifest = await call('Page.getAppManifest');
     const inst = await call('Page.getInstallabilityErrors');
     const errors = inst.installabilityErrors ?? inst;
     if (!Array.isArray(errors) || errors.length) failed++;
     console.log(`${url}\n  manifest: ${manifest.url || '(нет)'}, ${(manifest.data || '').length} байт\n  installabilityErrors: ${JSON.stringify(errors)}`);
     ws.close();
     await fetch(`http://127.0.0.1:${PORT}/json/close/${tab.id}`);
   }
   process.exit(failed ? 1 : 0);
   ```

3. Станция и контроль — одним прогоном, затем браузер закрыть:

   ```bash
   node pwa-check.mjs https://<station-domain>/ https://squoosh.app/ https://excalidraw.com/
   ```

Ожидание — у всех трёх найден манифест (у станции —
`https://<station-domain>/manifest.webmanifest`) ненулевого размера и
`installabilityErrors: []`, код выхода 0. Как читать отказ:

| Станция | Контроль | Значит |
|---|---|---|
| `[]` | `[]` | станция устанавливается |
| `no-manifest`, манифест 0 байт | `[]` | ссылка на манифест снова не в `<head>` (её убрал апстрим или конфликт при слиянии); сверить `curl -s https://<station-domain>/ \| grep -bo -e '</head>' -e 'rel="manifest"'` — первая ссылка обязана стоять раньше `</head>` |
| другая ошибка | `[]` | поломка станции: `errorId` называет критерий (иконки, `display`, worker); ошибка про worker — сперва повторить с `WAIT_MS=30000` |
| ошибка | ошибка | методика, а не станция: профиль, сеть, версия браузера |

Сам скрипт проверен 2026-10-05 на Chrome 154 по контролю: `squoosh.app` и
`excalidraw.com` — `[]`, страница без манифеста (`example.com`) — `no-manifest` и 0 байт,
ровно прежний симптом станции.
iPhone по CDP не проверяется: там установку смотрят руками — «Поделиться» → «На экран
„Домой“», подпись и иконка.

**Чем проверено.** При переносе на v1.17 — лёг без конфликтов; апстрим не добавил ни
ссылку на манифест в `<head>`, ни свою кнопку установки, дубля нет. Приёмка на живой
станции — процедура выше.

## Экран блокировки и динамический остров

`W07` · `a2564079`

Три правки, которые видно только с iPhone в руках.

**Прогресс на экране блокировки** — [useMediaSession.ts](../../web/hooks/useMediaSession.ts).
У живого потока `audio.duration` равен бесконечности, а `currentTime` считает
**соединение**, а не песню, поэтому система рисовала либо ничего, либо полосу,
обнуляющуюся на каждом переподключении. Позиция публикуется явно —
`mediaSession.setPositionState({duration, position, playbackRate: 1})`: длительность из
`/now-playing`, смещение — от той же метки `trackStartedAt`, по которой живут экранные
часы (её передаёт `PlayerCore`). Перепубликация раз в 5 с: между обновлениями система
экстраполирует сама, а за заблокированным экраном таймеры притормаживают. Позиция
зажата в `[0, duration]`: метка несёт буфер слушателя и может ненадолго оказаться в
будущем, а трек — пережить свою длительность из тега. Полоса **только для чтения**:
обработчики `seekto`/`seekbackward`/`seekforward` апстрим намеренно оставляет пустыми —
поток не перематывается. Когда длительность неизвестна, состояние **сбрасывается**
вызовом без аргументов, иначе на экране остаётся и продолжает ехать полоса прошлого
трека. Откуда станция знает длительность (сверка `library.db` с Navidrome) —
[deploy.md](deploy.md), «Экран блокировки телефона».

**Смена песни на экране блокировки** — [poll.ts](../../web/lib/poll.ts) и
[useStationFeed.ts](../../web/hooks/useStationFeed.ts). Причина была не в Media Session, а
в опросе: `pollWhileVisible` останавливал его целиком, пока вкладка скрыта, а
блокировка экрана на iOS — это ровно `document.hidden`. Метаданные переставали
обновляться, и система показывала трек, игравший в момент блокировки. Теперь у
`pollWhileVisible` третий параметр — функция, которая на каждой смене видимости решает,
опрашивать ли в фоне и как часто; при включённом эфире лента станции опрашивается в
фоне втрое реже (15 с против 5): дальше всех её видит экран блокировки, и опоздание на
15 с там незаметно. Повторная настройка на тот же темп таймер не перезапускает; на
переднем плане опрос стреляет сразу. Флаг эфира передаётся **ссылкой** (`RefObject`):
`useStationFeed` вызывается раньше `usePlayer` (тому сперва нужен ответ станции о маунте
Opus, #1300), а включение эфира не должно пересобирать подписку. Тем же параметром
пользуется опрос чата (W02).

**Эфир, включённый в скрытой вкладке, опрос возобновляет.** Флаг ссылкой
`pollWhileVisible` перечитывает только на смене видимости. Ушла вкладка в фон при
выключенном эфире — опрос встал; эфир включили с экрана блокировки, гарнитуры или
медиаклавишей — `tunedIn` сменился, а видимость нет, и опрос стоял дальше: метаданные на
экране блокировки замирали. Теперь возврат `pollWhileVisible` несёт `resync()` —
перечитать флаг сейчас; его зовут эффекты на `tunedIn` в `PlayerCore` (лента станции,
через `resyncPoll` из `useStationFeed`) и в `ClassicSkin` (комната, через `resyncPoll` из
`useRoomFeed`; эффект стоит после `useRoomFeed`, чтобы опрос уже существовал).
Выключение эфира в фоне тем же путём опрос останавливает. Опрос, поднятый из остановки,
стреляет сразу: данные старые ровно настолько, насколько долго он стоял (обычный уход в
фон по-прежнему ждёт первого тика — данные только что свежие). На переднем плане
`resync` ничего не меняет.

Возврат — **по-прежнему функция очистки**, у которой есть свойство `resync`, а не объект
`{stop, resync}`: пять апстримных мест зовут его как очистку (`useElapsed` и `Waveform`
дважды отдают прямо из эффекта, `useSignal` и `useStationFeed` вызывают), и объект
сломал бы каждое — лишние правки и конфликты при обновлении апстрима. `resync` после
очистки опрос не воскрешает.

**Текст на экране блокировки — как на карточке трека.** Апстрим отдавал в
`MediaMetadata` альбом как есть, и экран блокировки, шторка и CarPlay показывали заглушку
Navidrome «[Unknown Album]», которую карточка прячет через `ruAlbum` (W01); при пустых
полях там стояли имя продукта `SUB/WAVE` и английское «Live broadcast». Текст собирает
чистая функция `mediaText` в [mediaMetadata.ts](../../web/lib/mediaMetadata.ts) (вынесена
из хука ради теста): альбом — через `ruAlbum`, вместо `SUB/WAVE` — имя станции
(`dj.station` с `/now-playing`, его же показывает шапка; `PlayerCore` передаёт его в
`useMediaSession` параметром `stationName`), пока оно не пришло — запасное «AI радио»
(`ruStationName` в `ru.ts`, одно на шапку и экран блокировки), вместо «Live broadcast» —
«Прямой эфир». Пока говорит ведущий, исполнителем по-прежнему стоит его имя.

**Верх под динамическим островом** — `globals.css`. `viewport-fit=cover` плюс
прозрачная строка состояния уводят матовое стекло шапки **под** остров, и вокруг него
просвечивала размазанная страница. Полоса высотой `env(safe-area-inset-top)`
заливается плоским фоном (`.player-topbar::before`), остальная шапка остаётся матовой.
Высота — сам инсет, поэтому на устройствах без выреза правило нулевой высоты и не видно.

Выключение звука на iOS — в W05 (`el.muted`).

**Чем проверено.** Конфликты при переносе — только в комментариях; позицию на экран
блокировки апстрим v1.17 сам не публикует (`setPositionState` у него нет). Typecheck
веба; `npx tsx web/lib/poll.test.ts` (включение и выключение эфира в скрытой вкладке,
`resync` на переднем плане и после очистки, прежний контракт возврата и смены
видимости); `npx tsx web/lib/mediaMetadata.test.ts` (заглушка альбома, имя станции и
запасное, «Прямой эфир», ведущий в эфире); экран блокировки iPhone — владелец на живой
станции, в том числе эфир, включённый с экрана блокировки после ухода вкладки в фон
выключенной, и трек без тега альбома.

## Фон на Android

`W08` · `60b6f111`

Симптом со стороны слушателя: в Firefox на Android звук играет фоном несколько минут,
потом пропадает, а на экране блокировки плеера **нет вовсе** — ни названия, ни кнопок.

Причина не в Media Session — она у апстрима полная. Весь звук плеера идёт через Web
Audio — `createMediaElementSource(audio) → analyser → destination` ради визуализатора, и
для системы это перестаёт быть воспроизведением медиа: вкладке не дают фонового плеера,
а `AudioContext` усыпляют по энергосбережению. Обработчик `visibilitychange` не спасает —
он сработает, только когда пользователь вернётся, то есть уже после тишины.

Апстрим про эту опасность знает и сам называет её в шапке `useAnalyser` («routing the
element through Web Audio jeopardises lock-screen / background playback», #298), но
отключает Web Audio **только на iOS**. Форк распространяет отказ на телефоны целиком:
`isAndroidDevice()` рядом с `isIOSDevice()` в [platform.ts](../../web/lib/platform.ts) и
условие `isIOSDevice() || isAndroidDevice()` в `useAnalyser`
([hooks.ts](../../web/lib/hooks.ts)). Цена — визуализатор на телефоне переходит на
псевдослучайную заглушку апстрима, где он и так размером с ноготь. Приобретение —
радио, которое продолжает играть в кармане.

**Чем проверено.** Проверяется только с телефона: свернуть вкладку, подождать больше
пяти минут, посмотреть на экран блокировки — владелец. Без телефона (2026-09-23):
`createMediaElementSource` в плеере вызывается из одного места, и оно закрыто условием;
`/Android/` есть в User-Agent и у Firefox для Android; условие есть в собранных чанках
образа `web`. На v1.17 конфликт был только в комментарии `useAnalyser`; typecheck веба.

## Сверка заказа с коллекцией

`W09` · `7b3e5cda`

Пока слушатель набирает, ящик заказа
([RequestDrawer.tsx](../../web/components/skins/classic/drawers/RequestDrawer.tsx))
спрашивает комнату `GET /room/resolve?q=` — через 400 мс после последней клавиши
(набирают с телефона, без паузы каждая буква была бы запросом в Navidrome) и от трёх
символов (короче — ответом была бы вся коллекция). Показывает один из трёх ответов:
«нашёл в коллекции», список альтернатив кнопками или «такого нет». Точное совпадение
сразу запоминает его `songId`; выбор альтернативы подставляет в поле
`артист — название` и запоминает её `songId`; правка текста его сбрасывает.

**`songId` привязан к тексту, а не сбрасывается эффектом**
([requestPick.ts](../../web/lib/requestPick.ts)). Ящик помнит пару «`songId` + текст, при
котором он выбран» (без пробелов по краям, как запрос сверки) и отдаёт `songId`, только
пока поле совпадает с этим текстом. Сброс в эффекте на смену текста срабатывал и на
подстановку альтернативы: заказ, отправленный в первые 400 мс после выбора, уходил
свободным текстом. Теперь подстановку отвязывает только расхождение — правка человеком,
подсказка-заказ или очистка поля после отправки. Вернуть в поле ровно прежний текст —
значит вернуть и его `songId`: это тот же заказ.

Через паузу сверка видит подставленный текст и сама находит точное совпадение. При двух
одинаковых треках (альбом и сборник) она вернула бы первый по выдаче, а не выбранный
слушателем, поэтому точное совпадение привязывается, только если к этому тексту ещё
ничего не привязано (`bindExact`).

**Отсутствие трека отправку не запрещает.** Ведущий читает записку целиком и умеет
разбирать настроение («что-нибудь бодрое из восьмидесятых»), а не только
«артист — название»; запрет превратил бы заказ в поиск по каталогу. Комната недоступна —
заказ уходит текстом, каскад станции его разберёт.

**Ответ сверки объявляется скринридером.** Три ответа лежат в обёртке
`aria-live="polite"`, которая есть в DOM всегда, даже пустая: живую область, появившуюся
вместе с текстом, скринридеры не озвучивают. Обёртка — простой блок, отступы ответов
схлопываются сквозь неё, вёрстка прежняя.

**Спрашивается комната, а не контроллер:** у контроллера весь поиск по библиотеке
закрыт `requireAdmin`. Как комната сверяет (командное слово, падеж, неточное
название) — [room/README.md](../room/README.md), «Сверка с коллекцией».

`songId` идёт по цепочке `RequestDrawer → ClassicSkin.submitRequest →
PlayerCore.submitRequest → stationClient.submitRequest`, и на каждом шаге он
**необязательный** — остальные пять скинов о точном заказе не знают и работают без
правок. `PlayerCore` до сети проверяет тело зеркалом схемы контроллера
(`listenerRequestSchema` в `web/lib/schemas.generated.ts`, поле `songId`), а
`JSON.stringify` выбрасывает `undefined` сам — тело заказа без `songId` остаётся прежним.
Что контроллер делает с `songId` —
[controller-changes.md, «Точный заказ по songId»](controller-changes.md#точный-заказ-по-songid).

**Чем проверено.** `npx tsx web/lib/requestPick.test.ts` (подстановка альтернативы,
правка, пробелы по краям, очищенное поле, сверка не перебивает выбор). Зеркало схемы с `songId` встало генерацией до
переноса фичи (`f31c1d0f`), его hunk совпал; конфликты — только в комментариях
сигнатур. Линтер и typecheck веба; на живой станции — заказ из подсказки уходит с
`songId`.

## Скачивание трека

`W10` · `bb5d5d97` · [спека](specs/2026-09-22-track-download-design.md)

Кнопка со стрелкой вниз — на карточке текущего трека (рядом с сердцем) и в каждой
строке «Уже прозвучало» (`CenterStage.tsx`, `drawers/TimelineDrawer.tsx`). Ведёт на
`/room/download?id=…` ([download.ts](../../web/lib/download.ts)) обычной ссылкой с голым
атрибутом `download`: имя файла задаёт заголовок ответа комнаты, а значение атрибута
создало бы второй источник истины, который всё равно проигрывает заголовку. Ссылка, а не
кнопка с состоянием: `CenterStage` — под `memo`, и хук с сетевым состоянием это сломал
бы. Значок — `ArrowDownToLine`, а не `Download`: последний уже занят кнопкой установки в
шапке (W06).

**`/room/` выведен из-под service worker** ([sw.js](../../web/public/sw.js)). Апстримный
worker пропускает мимо себя только `/stream.*` и `/api/*`, а всё прочее кладёт в Cache
Storage (`networkFirst`) — каждый скачанный трек (8–14 МБ) оседал бы второй копией на
телефоне, а отдача шла бы через `respondWith`, где установленное приложение на iOS ведёт
себя непредсказуемо.

До минуты после смены трека карточка и лента могут показывать разные записи
(`useStationFeed` откладывает карточку на буфер Icecast, `state` — нет), но на скачивание
это не влияет: `id` кнопки на карточке в этот момент равен `history[0]`, то есть уже
прозвучавшему треку.

**Отказы.** Комната отвечает честным HTTP-кодом (400/403/404/429/502) и текстом причины
в теле. Но ссылка того же origin лишь просит браузер сохранить тело ответа, а Chromium
(Chrome, Edge, Chrome на Android) при коде ошибки загрузку обрывает и тело не пишет — в
«Загрузках» будет «Сбой» без текста причины (зато и конверт ошибки под именем песни не
появится). Файл с текстом причины сохранит браузер, который тело ошибки не отбрасывает
(Firefox, Safari — проверяется руками при выкатке). Тост вместо файла потребовал бы
предварительной пробы — второго запроса и состояния в компоненте под `memo`. Контракт
`/download` — [room/README.md](../room/README.md).

перечитать `libraryKeys.folders()`: клиент не повторяет запросы сам, а карточка с
запросом не размонтируется, так что переоткрытие диалога ошибку не лечит) и
действительно пустое дерево — подсказка, что папки появляются после Reconcile with
Navidrome, когда Navidrome отдаёт станции настоящие пути. Треки без настоящего пути
считаются (`withoutPath`) и называются: ни правило Folder, ни жанры папок их не видят.

которые есть сейчас, и флажок есть только у них, а у корня его нет вовсе. Если папку из
правила переименовали или она пропала, строка правила показывает её путь со счётчиком 0,
а в редакторе под деревом такие пути (`untickablePaths` в `folderTree.ts`) стоят
списком «Not in the folder tree…» с крестиком — снять их можно, не удаляя правило.
Пока дерево не загрузилось из-за ошибки, тем же списком («Folders in this rule»)
показываются все пути правила. Выбор плейлиста в том же редакторе такого списка не
имеет: пропавший плейлист в редакторе не виден, правило с ним удаляют и заводят заново.

результат генерации (`f31c1d0f`), а не правки руками.

Basic-токеном, что у `adminFetch`: своей копии пароля у комнаты нет, она проверяет его

(409 по-прежнему успех), решение в комнату — `POST` отдельным `fetch`.

заблокированных альбомов и правила по названию остались бы в предложениях. Отсев идёт

## Сердечко спрашивает /api/like только за свой трек

`W14` · `ee166dc2`

Утечка запросов: 28.09 — около 940 запросов `/api/like` разом, раз в четыре минуты, то
есть на каждой смене трека.

**Причина.** Сердечко (`LikeHeart` в
[CenterStage.tsx](../../web/components/skins/classic/CenterStage.tsx)) живёт внутри
`AnimatePresence` с ключом по треку: на смене трека прежняя копия уходит анимацией
выхода. В скрытой вкладке кадров нет, выход не завершается, и копии копятся сутками.
`useTrackLike()` брал трек из ленты станции — общий для всех копий, — поэтому каждая
копия спрашивала `/api/like` на каждой смене трека.

**Исправление** — в [sharedHooks.ts](../../web/components/skins/sharedHooks.ts):
`useTrackLike(songIdFor?)` принимает трек, для которого нарисовано сердечко, а
`LikeHeart` получает `songId` пропсом. Уходящая копия держит свой трек и заново не
спрашивает. Аргумент необязательный: без него хук берёт трек из ленты, как у апстрима, —
прочие скины зовут его без аргумента и ведут себя по-прежнему.

Раздела в прежнем описании патча у этой правки не было — она жила в нём строкой без
хозяина. Апстрим v1.17 утечку не чинил: `useTrackLike()` по-прежнему берёт трек из ленты,
`LikeHeart` по-прежнему под `AnimatePresence`.

### Копии сцены в скрытой вкладке

Правка выше сняла с копий запросы, но не сами копии. После W07 лента опрашивается и в
скрытой вкладке, пока играет эфир, — значит, сцена меняет трек там, где выход не
завершится: около 360 копий блока названия (сердечко, 👎, скачивание) и обложки за
сутки, каждая подписана на контексты ленты и дизлайков и перерисовывается с ними.

**Пока вкладка скрыта, сцена не получает новых пропсов.** `ClassicSkin` отдаёт в
`CenterStage` не `nowPlaying`/`trackStartedAt` ленты, а их значения на момент, когда
вкладку скрыли ([useHeldWhileHidden.ts](../../web/hooks/useHeldWhileHidden.ts)); на
`visibilitychange` к видимой — актуальные. Ключ `AnimatePresence` в скрытой вкладке не
меняется, копий нет; на возврате сцена делает один переход сразу к текущему треку.
Хук — новый файл форка, а не правка `CenterStage`: конфликтов при обновлении апстрима
меньше.

**W07 это не задевает:** экран блокировки получает метаданные из `PlayerCore`
(`useMediaSession({ nowPlaying: feed.nowPlaying, trackStartedAt: feed.trackStartedAt })`)
— прямо из ленты, мимо пропсов сцены. Строка «сейчас играет» в чате, отметки 👎
(`dislikeWindowKey`) и подсветка фона тоже берут живую ленту.

Другой путь — рисовать сцену без `AnimatePresence`, пока `document.hidden`, — отвергнут:
смена видимости меняла бы дерево, и блок названия перемонтировался бы на каждом
сворачивании (с новым запросом `/api/like`), а правка легла бы внутрь апстримного
`CenterStage`.

**Как измерить** (владелец, Chrome на компьютере). Открыть плеер, включить эфир (звук
можно убрать ползунком — опрос в фоне держится на включённом эфире, а не на громкости),
открыть DevTools **отдельным окном** (Undock) и в консоли запустить запись раз в 10 минут:

```js
window.__probe = [];
setInterval(() => window.__probe.push({
  t: new Date().toLocaleTimeString(),
  hidden: document.hidden,
  titles: document.querySelectorAll('.v3-title').length,     // копии блока названия
  covers: document.querySelectorAll('.v3-cover-glitch img').length,
  nodes: document.getElementsByTagName('*').length,
  heapMB: Math.round((performance.memory?.usedJSHeapSize ?? 0) / 1e6),
}), 600_000);
```

Затем переключиться на другую вкладку (плеер скрыт) и оставить на ночь. Утром, **не
возвращаясь на вкладку плеера**, — в том же окне DevTools `console.table(__probe)`.
Отстыкованный DevTools остаётся подключён к скрытой вкладке, `hidden` в строках должен
быть `true`. Память вкладки без DevTools видна в диспетчере задач Chrome (Shift+Esc,
«Объём памяти»). До правки `titles`, `covers` и `nodes` растут на каждой смене трека
(~15 в час), после — `titles` и `covers` не больше 2, `nodes` не растёт.

**Чем проверено.** Typecheck веба; на живой станции — число запросов `/api/like` в
журнале Caddy после нескольких смен трека при скрытой вкладке; копии сцены — замер выше
(владелец). Автотеста нет: у веба нет DOM-окружения для тестов (ни jsdom, ни
testing-library), а логика хука — одна строка выбора.

## Сборка

Своего Dockerfile и оверлея у веба нет: русский интерфейс и все фичи — в исходниках
форка, а образ собирает многоступенчатый `web/Dockerfile` апстрима (deps → build →
runner на `node:24-bookworm-slim`). Node, npm и зависимости живут только внутри сборки.

Образ собирается на хосте станции из клона форка `~/radio`:

```bash
# на машине разработчика — ревизия на хост станции
bash station/tools/push-to-station.sh <ref>          # по умолчанию HEAD

# на хосте станции — сборка под сторожем памяти, затем подъём
cd ~/radio && bash station/tools/guarded.sh sudo docker build -f web/Dockerfile -t subwave-web:1.17.0-ru \
  --label org.opencontainers.image.revision=$(git rev-parse HEAD) \
  --build-arg SUBWAVE_BUILD_VERSION=1.17.0-ru+$(git rev-parse --short HEAD) .
cd <deploy-dir>/subwave && sudo docker compose up -d web
```

**Доставка ревизии** — [push-to-station.sh](../tools/push-to-station.sh): `git bundle` всех
веток и тегов → `scp` → `git fetch` в `~/radio` → `checkout -f --detach <sha>` и
`git clean -fd`. Хосту не нужен доступ к приватному origin, а дерево приходит с LF (архив
с Windows принёс бы CRLF). Хост и SSH — из `station/.env`. Клон на хосте **руками не
правится**: следующий вызов затрёт правки. Клон временный: после сборки и выкатки —
`rm -rf ~/radio`, следующий вызов создаст его заново.

**Сторож памяти** — [guarded.sh](../tools/guarded.sh). Хост станции делит ОЗУ с чужими
службами, и память кончается у него раньше, чем у cgroup контейнера: сборка Next
(`npm ci` и `next build` внутри `docker build`) может увести весь хост в глобальный OOM —
`tsc` однажды пять раз подряд уронил его так. Сторож запускает команду и каждые 0.5 с
смотрит `MemAvailable`; ниже порога (`MIN_AVAIL`, по умолчанию 500 МБ) снимает команду
строкой `GUARD MemAvailable … — снято` и выходит с **кодом 3**. В конце любого прогона
печатает минимум `MemAvailable` за прогон. Код 3 — не ошибка сборки, а её снятие:
повторять вслепую нельзя, сначала разобраться, кто занял память, и выбрать время. Код
сборки при обычном завершении сторож возвращает как есть.

`SUBWAVE_BUILD_VERSION` — версия в подвале админки, вшивается в клиентский бандл при
сборке; без неё берётся версия из `web/package.json` апстрима. `+<sha>` в ней и метка
`org.opencontainers.image.revision` называют ревизию форка: тег один на все сборки, а
метку живого контейнера сверяет [«Перед выкаткой»](controller-changes.md#перед-выкаткой--сверка-живого-образа-с-клоном).

**Образ берётся только свой.** Он живёт локально на хосте и в реестр не публикуется;
[docker-compose.override.yml](../deploy/docker-compose.override.yml) задаёт
`image: subwave-web:1.17.0-ru` и `pull_policy: never`. Апстримный образ `web` по
`compose pull` вернул бы английский интерфейс без единой нашей фичи. **Тег обязан
совпадать с версией апстрима**, из которой собран: иначе после обновления контроллер
уедет вперёд, интерфейс останется старым, и заметить это будет не по чему.

**Если сборка упала на `Turbopack is not supported ... swc-linux-x64-musl`** — это не
платформа, а битый слой `deps` в кэше docker (неполные `node_modules`). Лечится
`--no-cache` (проверено 2026-09-22, на v1.8 сборка из чистого кэша — около двух минут).

**После подъёма** — проверки из разделов фич: `SUB/WAVE` на главной — 0 и иконка 512
глазами (W04), установимость по CDP (W06), английских подписей на странице плеера нет,
кроме перечисленных в W01 — включая диалог «Оформление» (значок палитры в шапке), крестик
ящика и тосты; раздела «Вид плеера» в диалоге нет, клавиша `S` ничего не делает, а в
`/admin` тот же диалог по-английски (W01); чат и Web Push, сверка заказа, скачивание, 👎
и вкладка Blocked; экран блокировки iPhone — владелец.

## Линтер, typecheck и тесты

Только на машине разработчика: на хосте станции `npm ci` и `tsc` уводят его в
глобальный OOM. Проверяется ровно закоммиченная ревизия, вне рабочего дерева
репозитория — `node_modules` в него не ложится:

```bash
L=<lint-dir>; rm -rf "$L/web"; mkdir -p "$L"
git archive --format=tar HEAD web | tar -x -C "$L" --exclude=web/AGENTS.md
(cd "$L/web" && npm ci --ignore-scripts && npm run lint)
```

`web/AGENTS.md` в дереве апстрима — симлинк на `CLAUDE.md`; на сетевом диске симлинк
не создаётся, и распаковка на нём спотыкается, а линтеру он не нужен. `npm run lint` —
это `eslint . && tsc --noEmit`. **Ожидание — 0 ошибок** (предупреждения — апстрима). На
v1.8 цепочка не доходила до `tsc`: eslint останавливался на трёх старых ошибках патча
(инлайн-стиль ползунка и неиспользуемые `fill`/`opaque` знака), а у `tsc` была своя — в
`roomPush.test.ts`; при переносе исправлены все (W03, W04, W05).

Тесты — отдельные скрипты, своего раннера у веба нет; `tsx` не входит в зависимости
веба, `npx` подтянет его сам. Прогоняет их встроенный раннер Node через `tsx --test`:

```bash
cd "$L" && npx tsx --test web/lib/*.test.ts
```

Каждый скрипт печатает ✓/✗ по случаям и выходит с ненулевым кодом при падении; раннер
запускает каждый файл отдельным подтестом, доводит до конца все и сам выходит с
ненулевым кодом, если упал хоть один. Прежний цикл `for … npx tsx …$t.test.ts || break`
этого не давал: `break` обрывал остальные файлы, а цикл завершался с кодом 0 — падение
выглядело успехом (проверено заведомо падающим скриптом, 2026-10-09). Модули чистые,
поэтому скрипты идут и без `npm ci`, и из рабочего дерева. Шаблон захватывает все
тринадцать наших (`ru`, `requestPick`, `listener`, `roomRules`, `roomNotify`, `roomPush`,
`serviceWorker`, `roomDislikes`, `folderTree`, `dislikeSuggestions`, `poll`, `volume`,
`mediaMetadata`) и апстримный `audienceStats.test.ts`.

## Обновление апстрима

Новая версия апстрима вливается слиянием, а не переносом патчей: `main` опубликована,
история не переписывается.

```bash
git fetch upstream --tags
git switch -c port-X.Y.Z main
git merge vX.Y.Z
```

**Конфликты** разрешаются по смыслу фичи, а не по старому hunk: смысл — разделы этого
документа. Чаще всего апстрим просто ужимает свои комментарии рядом с нашими (на v1.17
так было у W05, W07, W08, W09, W14) — тогда наш абзац дописывается к его версии. Если
апстрим переписал компонент целиком, фича делается заново поверх его версии, как W12 на
TanStack Query; раздел фичи после этого описывает новую реализацию.

**Таблица вердиктов** — `station/docs/port-X.Y.md` по образцу
[port-1.17.md](port-1.17.md): строка на фичу — «Фича · Вердикт · Что изменилось при
переносе · Чем проверено». Отдельно сверить, не сделал ли апстрим что-то сам — тогда
вердикт «апстрим сделал», и наша правка сокращается до недостающего:

| Фича | Что сверить у новой версии |
|---|---|
| W02 | клавиша `5` и тип `PlayerDrawer` свободны |
| W03, W10 | обработчики `push`/`notificationclick` и исключение `/room/` в `web/public/sw.js` |
| W04 | новые места `SUB/WAVE` на странице плеера и в `layout.tsx`/`manifest.ts`; кто рисует иконки из `DiscMark` |
| W06 | своя ссылка на манифест в `<head>` или кнопка установки (`beforeinstallprompt`) у апстрима — дубль |
| W07 | `setPositionState` у апстрима; третий параметр `pollWhileVisible` и `resync` у его возврата; новые вызывающие `pollWhileVisible` |
| W08 | условие отказа от Web Audio в `useAnalyser` |
| W12, W13 | переписанные апстримом `BlockRulesCard`, `BlockedTabContainer`, `queries.ts` |
| W14 | `useTrackLike` и `LikeHeart` под `AnimatePresence`; пропсы `CenterStage` в `ClassicSkin` идут через `useHeldWhileHidden` |

**Новые английские строки апстрима в классическом скине переводятся** в том же
переносе, как «More/Less» → «Ещё/Свернуть» на v1.17 (вердикт W01). Искать по диффу
апстрима между версиями: `git diff vСТАРАЯ vX.Y.Z -- web/components/skins/classic
web/components/player web/components/ThemeSwitcher.tsx web/components/ui/sheet.tsx` —
строковые литералы и текст в разметке; новая строка `ThemeSwitcher` — в обе половины
`COPY`. Новые скины апстрима на страницу плеера не попадут сами: `PAGE_SKINS` в
`PlayerShell.tsx` — только `classic`.

**Зеркало схем `web/lib/schemas.generated.ts` правится только генерацией** из схем
контроллера (`controller/src/schemas/*.ts`, генератор
[gen-schemas.ts](../../controller/scripts/gen-schemas.ts), `npm run gen:schemas` в
`controller/`). Руками его не трогают: это копия тех же схем, которыми контроллер
проверяет запросы, и CI апстрима ([lint.yml](../../.github/workflows/lint.yml))
перегенерирует его и падает на любом расхождении. Генератор пишет в
`../web/lib/schemas.generated.ts` относительно `controller/`, поэтому в каталог линтера
выкладываются оба пакета:

```bash
# из корня репозитория, после закоммиченного слияния: git archive берёт HEAD
L=<lint-dir>; rm -rf "$L"; mkdir -p "$L"
git archive --format=tar HEAD controller web | tar -x -C "$L" --exclude=controller/AGENTS.md --exclude=web/AGENTS.md
(cd "$L/controller" && npm ci --ignore-scripts && npm run gen:schemas)
diff -q "$L/web/lib/schemas.generated.ts" web/lib/schemas.generated.ts && echo SCHEMAS-SAME
```

Конфликт в самом зеркале при слиянии руками не разрешается: берётся любая сторона, а
файл перегенерируется из уже слитых схем. Расхождение — сгенерированный файл
копируется в репозиторий отдельным коммитом, как `fix(web): зеркало схем после переноса`
(`f31c1d0f`). На v1.17 фичи переносились по одной, и этот коммит встал после фич
контроллера и **до** фич веба, опирающихся на зеркало (W09 — `songId`, W12 — `folder`,
`RULE_PATH_MAX`), — их правки зеркала совпали с уже сгенерированным, а не конфликтовали.
